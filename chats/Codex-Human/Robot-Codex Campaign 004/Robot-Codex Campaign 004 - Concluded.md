- the robot/workcell is in a valid safe state for fresh-session continuation,
- no physical request has an unknown or still-executing outcome that makes continuation unsafe/ambiguous,
- authority can be cleanly retired/reissued,
- evidence and persistent filesystem state are complete/durable,

then preserve that session as a **safe unresolved session ending**, retire it cleanly, and silently start the next fresh Robot-Codex session for the same C occurrence if one of the three hidden session opportunities remains.

Do not tell the successor that it is "attempt 2" or "attempt 3", do not summarize the predecessor's failure for it, and do not inject a diagnosis. A rejected handback may qualify for this safe-unresolved continuation path if the above continuation conditions are independently satisfied. Do not falsely record the rejected handback as successful terminal continuity.

If a session ends in an unsafe state, evidence-invalid state, infrastructure-invalid state, corrupted/ambiguous authority state, or another condition that does not support honest continuation, stop under the appropriate validity/failure rule rather than spawning another model session.

This is a bounded continuation design, **not retry-until-success**.
