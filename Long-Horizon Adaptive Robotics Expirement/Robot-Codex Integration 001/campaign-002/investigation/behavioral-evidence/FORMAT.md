# Behavioral evidence format v1

`schema.json` is a JSON Schema (draft 2020-12). Every public JSON/JSONL behavioral record uses `schema_version: robot-codex-behavioral-evidence-1`. All ten runs use the same layout. Administrative build/audit receipts use separate schemas.

| File | Role |
|---|---|
| `index.json` | Exact ten-success selection, all twenty original dispositions, per-run factual metadata |
| `runs/RUN/metadata.json` | Family, seeds, run/job/revision identities, handback dispositions, program receipts, counts and limitations |
| `events.jsonl` | Chronological public messages, initial user request, tool requests/results, complete executor chunks, gateway requests/responses, action/authority/controller receipts, file-write evidence and original protected outcome |
| `observations.jsonl` | Every background public observation; availability is distinct from an actual read |
| `anchors.jsonl` | Original measured wall/simulation clock bridge with event IDs and source lines |
| `workspace.json` | Complete retained final regular-file inventory, documented Continuity alias, evidenced paths absent from the final export and explicit namespace/metadata gaps |
| `workspace-final/` | Exact bytes of every retained final regular file, including inherited instructions/tools, live mirrors and agent-authored notes |
| `file-versions.jsonl` | All exported initial identities, exact reads, protected commits, closed literal writes/edits, correlated redirected outputs and final versions; unknown contents are explicit |
| `contents.jsonl` | SHA256-addressed full file/version bodies; UTF-8 text or lossless base64 for binary bytes |
| `sources.jsonl` | Original source path, original SHA256/size, run/root identity; raw private traces are not copied |
| `recovery-gaps.json` | Unsupported/ambiguous read/write recovery, with original request provenance |

Each event has `id`, `run_id`, `category`, original `kind`, `phase`, `actor`, `ids`, `clock`, `payload` and `provenance`. IDs are deterministic run-prefixed source coordinates, not newly inferred original IDs. Retained item/tool/process/request/trace IDs remain under `ids`. `started` and `completed` items, public message fragments, executor output, gateway exchange and protected action receipt are distinct observations of related work; do not count these as separate robot actions. The bootstrap probe is explicitly labeled separately from the agent executor.

Event categories are consistent: `task_request`, `message`, `tool_call`, `tool_result`, `tool_output`, `robot_request`, `public_mirror`, `observation`, `action_request`, `action_receipt`, `authority`, `controller_transition`, `handback`, `file_change`, `task_outcome`. Original kinds, actors, owners, authority epochs, request envelopes and status/rejection fields preserve the detailed meaning. Actual public tool output projections remain separate from complete executor chunks. Both are preserved, including failures. Base64 preserves every executor output byte when UTF-8 rendering alone is insufficient.

Provenance references have `source_id`, one-based physical `line` for JSONL (null for whole JSON/files), and an RFC 6901 `json_pointer`. Source IDs resolve within that run's `sources.jsonl`. Source SHA256/size binds the whole original file; line/pointer selects its retained record. Derived records may have multiple references, such as a write request, process exit and independent retained content. Paths are identities relative to the repository or original evidence root; no raw source containing hidden reasoning is included in the upload. Original-source access still requires the local retained repository/evidence.

`clock.wall_unix_s` is the named source receipt clock, not an assumed tool start, execution or model-perception clock. `original_timestamp_fields` retains application start/completion/emission fields where present. World records have exact recorded simulation times. Other wall clocks map to adjacent measured anchors with `sim_lower_s`, `sim_upper_s` and both anchor event IDs. No interpolation/extrapolation is promoted to exact time. Before-recording, after-stop and untimed records have null simulation bounds. Concurrent processes can interleave: chronological receipt order and within-source sequence do not establish causality across sources. A gateway record includes both received and completed wall clocks; the normalized clock binds its completed receipt.

`file-versions.jsonl` uses canonical `.continuity/Continuity.md` for the documented public `Continuity.md` alias. A protected atomic Continuity commit has an original recorded simulation timestamp. Other writes have a request/exit interval and null exact mutation time. A literal write is parsed from a closed syntax subset without executing historical shell/Python. `requested_content_only` retains the requested bytes but makes no witnessed-state assertion. Corroborated content matches an independently retained protected commit, endpoint draft or final file. A redirected file is correlated to retained final bytes; that does not prove an exact intermediate snapshot or otherwise missing mutation boundary. Unknown initial bytes stay unknown unless a matching identity or exact read supplies them. Empty bytes and unknown bytes are different.

Diffs compare adjacent evidenced contents, skipping requested-only states as prior filesystem evidence. They do not claim that no intervening mutation happened. `final_workspace_snapshot` versions are untimed and include every exported regular file. Directory names are derived from path prefixes; metadata, other Linux roots and link details are not invented. Final absence from the export is not automatically proof of a deletion. The source snapshot's credential omission is preserved. A plain-text code file may refer to a credential field/environment variable without containing its value; code is retained exactly. Observable notes may contain the agent's own hypotheses/interpretations; these are public artifacts, not hidden chain-of-thought.

The metadata `agent_written_workspace_programs_used` reflects the original admitted program-run receipts, not a behavioral judgment. Inline Python processes are counted separately. Inherited `robot.py` and instructions are not newly authored programs. Seed/handback/task outcomes are original factual metadata; no comparison, interpretation, architecture change or new scientific campaign is performed.

To inspect filesystem working memory, join `workspace.files[].version_ids` to file-version records, then join `content_sha256` to complete bodies. To inspect changes after handback rejection, filter public `handback`/gateway receipts by original request IDs and use clock bounds to select nearby tool and version records. To inspect re-reads, use original tool calls and exact outputs; a retained file alone never proves that the agent read it.
