# Raw prepared tool-result capture: source analysis

This is dependency inspection and a prospective recommendation. No model, queue, production edit or historical reassessment was performed for this analysis. The original smoke008 failure and incomplete displayed Tools.md bytes remain unchanged.

The smallest supported observability change is an additive bootstrap copy enabling `thread/start.experimentalRawEvents`. Retain both `function_call` / `function_call_output` and `custom_tool_call` / `custom_tool_call_output`. The local generated schema supports these forms. Each raw notification carries `threadId`, `turnId`, and a ResponseItem. Function output call_id is nullable in the schema: evidence must require a nonempty explicit matching ID. Output is a string or an ordered content-item array; a text proof must consume the complete text form and reject unknown/nontext content.

The pinned reference source emits raw prepared items after tool formatting and code-mode truncation: session/mod.rs3537-3666 and4163-4170; thread_lifecycle.rs319-334; bespoke_event_handling.rs1163-1176. The outward method spelling is rawResponseItem/completed (protocol/common.rs1957). Raw item clones precede history.record_annotated_items, so this is the prepared conversation-item boundary, not proof of the exact serialized next request, model attention or subsequent reasoning. Warehouse metadata is removed from app notifications; an optional media filter exists. Neither permits silently claiming complete text where observed bytes are incomplete.

Direct exec calls can use the exact dispatched call ID: process_manager.rs244 places context.call_id into native toolCallId; context.rs413-421 and578-602 return the output with that call ID. This remains subject to actual invocation, environment, lifecycle, empty stderr, integer exit zero and complete byte correspondence.

Code-mode nested IDs are different. delegate.rs323 creates a fresh exec-UUID. context.rs62-64 explicitly states runtime_tool_call_id is not the Codex tool-call ID. The resulting JSON (context.rs448-477) contains chunk_id, wall_time_seconds, exit_code, session_id, original_token_count and output, but not event_call_id. event_call_id is retained for post-tool hooks only. A chunk ID in returned JSON is not an authoritative native process join without an independently observed matching ID.

The retained installed commandExecution schema has no parent/cell ID. Fetched reference source contains model_context and originating-call features absent from that schema. Therefore the tag is not installed-build attestation; no tag-only parent relation is admissible. A finite single-command wrapper may support an explicitly labeled unique-call correlation, with the strict conditions in the separately declared RAW_TOOL_RESULT_EVIDENCE_V1.md. General JavaScript, concurrent/yielded/multiple calls, ambiguity, missing identities or a substring match remain unsupported.

A transparent H2 observer is a larger change and does not solve this gap alone. CompleteToolCall.output_json is the nested value returned to JavaScript; JavaScript may print only a fraction. ExecuteEvent content subsequently passes core sanitization, error formatting and token truncation. The H2 runtime ID is separate from the generated native call ID. Proper passive capture would also need HTTP2/HPACK/gRPC framing, compression, trailers, caps and closure receipts. No reconstruction from those lower-layer bytes should be called prepared output.

Recommended implementation boundary: preserve bootstrap v2, add v3 raw flag and receipt only, retain durable logging/redaction and all model/configuration/isolation/history settings. The recognizer adds a separately labeled proof while leaving a false displayed-output projection false. It consumes the actual complete prepared output, unwraps only known complete source-bound envelopes, requires exact full equality with authenticated complete executor stdout, and passes every byte through the existing trusted source matcher. Unknown formatting, caps, truncation, redaction, errors and incomplete identities fail closed. Retain only the approved observability scope; do not surface raw reasoning or ambient credentials in reports.

Validation must cover raw absence, missing prefixes, unknown envelopes, false/noninteger exit, foreign/duplicate identities, overlap, multiple or unresolved commands, truncation, changed protected sources and byte mismatches. A no-model native option preflight can show acceptance only. New source/binary/schema bindings and full fresh qualification are required before empirical admission. Existing thresholds, policy and source bytes stay unchanged.

Every acquired reference file and local schema/input is hash-bound in raw-tool-result-analysis.json; additive source-evidence receipts preserve URL, tag, size, SHA and retrieval status. Public source license is retained in sibling native-output-source-001/LICENSE and referenced by exact official tag URL. These reference files are not asserted to be byte-identical build inputs of the installed executable.
