# Native output paths after smoke008

Smoke008 remains failed. Its captured executor sent all 13,029 bytes of Tools.md; the native displayed delta and completed command item contain only the final 4,837 bytes. The missing first 8,192 bytes are not present elsewhere in the retained public events. This is not evidence that the model received the same shortened result: the actual tool-result body and original output-cap arguments were not captured.

The newly retained `rust-v0.157.1` dependency source identifies distinct paths. In `exec-server/src/process.rs`, new event subscribers receive replay history followed by live events under a common lock. That layer retains enough for this four-event, 13 KiB process. In `core/src/unified_exec/process.rs`, the native process task writes to a retained output buffer and a separate broadcast channel. Its `output_receiver()` subscribes to that broadcast without replay. `process_manager.rs` creates the process before starting the display subscription, and later collects the retained output buffer separately for the tool response.

`async_watcher.rs` builds the displayed transcript from the later subscription. Its completion helper prefers any nonempty transcript to the fallback collected output. Consequently, source-level scheduling can produce a partial displayed transcript even when the retained tool-result buffer is complete. This fits the observed prefix/tail and item-start ordering. It does not prove the unique cause or actual model-visible bytes of smoke008. The downloaded tag matches the installed version label, but is not an exact executable build attestation.

The declared six-case standalone `command/exec` diagnostic was rejected before source freeze or queue submission. The newly inspected `app-server/src/command_exec.rs` converts cwd to a local path and launches local PTY/pipes, or the local Windows sandbox. It does not use the remote ExecBackend. The planned test therefore cannot establish the required isolated remote route; local fallback would answer a different question. Its declaration and guarded scaffolding remain as a rejected prospective design, with zero empirical attempts.

The next supported investigation is complete result observability on the existing model code-mode path. The retained gRPC schema exposes uniquely identified tool calls and completion-result bodies, as well as executed-cell output. Any capture must forward the original bytes unchanged, preserve isolation and bounded resources, reject ambiguity and missing bytes, and distinguish tool availability, returned cell output and model attention. It may not manufacture displayed output from executor capture or relax startup verification. A patch to native display code is a separate possible repair, requiring a source-bound build and complete fresh qualification.

Exact downloaded URLs, failed lookups, byte identities and source dependencies are retained in [the analysis JSON](native-output-path-analysis.json) and the three `native-output-source-001/source-evidence*.json` receipts. The original [smoke008 diagnosis](smoke-008-output-delivery-analysis.md), failed assessment and unlaunched pilots are unchanged.
