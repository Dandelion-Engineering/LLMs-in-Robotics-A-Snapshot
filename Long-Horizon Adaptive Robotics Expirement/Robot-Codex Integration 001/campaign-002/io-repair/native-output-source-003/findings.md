# Pinned code-mode truncation source foundation

This packet retains official `openai/codex` **rust-v0.157.1** files with URL, retrieval time, byte count and SHA256 receipts. It is code review, not installed-binary attestation or an assessment of Smoke022. No native/model/queue/assessor call or runtime edit occurred.

The ordering is nested tool JSON → code-mode text items → response adaptation → outer truncation → separate script-status/timing header. `context.rs:448–477` constructs the nested result, whose output may already have its own cap; `completion.rs:20–23` serializes that nested value. The public protocol description at `description.rs:33` specifies JSON.stringify for non-string `text` values. The inspected Rust files do **not** expose that JavaScript host helper implementation; its documented contract must not be mislabeled independently inspected code. The response adapter preserves returned text verbatim.

`code_mode/mod.rs:278–288,309–326` selects the all-text truncation path. `output-truncation/lib.rs:52–104` combines text items in order, inserting LF before each item only when the accumulator is already nonempty. If within budget it returns original separate items. If over budget it replaces their text with one formatted item. `output.rs:20–34,62–67` adds/updates a separate leading status header after this operation.

`unified_exec/mod.rs:79,227–228` supplies the explicit outer budget or default **10000 tokens**. `string/truncate.rs:4,15–34,56–83,86–152` implements approximate four UTF8 bytes per token, a half-budget prefix and remaining-half suffix rounded inward to UTF8 scalar boundaries. These slices are unchanged; the middle is replaced by a literal ellipsis/count marker, with no added separator. A warning header is prepended. Header/marker overhead is additional to retained slices. The counts use ceil(bytes/4), not tokenizer measurements; marker count uses original bytes minus nominal budget and therefore does not account exactly for additional UTF8 boundary loss.

For a default all-text budget, the nominal unchanged head is20000 UTF8 bytes (possibly fewer at a scalar boundary). This supplies a possible foundation for a **complete individual file wholly inside that head**, if a later prospective method independently binds the actual wrapper, prepared output, source-derived boundary and exact file serialization. It never proves a file crossing the cut, complete aggregate command output, model attention, or omitted content. This packet implements no new evidence rule and changes no prior verdict.

Concrete counterexamples: a native marker inserted inside a JSON string can leave valid but modified JSON; a source file may itself contain marker/warning text; file A may be complete while adjacent file B crosses the cut; JSON escaped-byte offsets differ from decoded-file offsets; inner exec truncation may already have lost bytes before the outer truncation. Consequently do not parse head+marker+tail as complete original JSON, infer the boundary by marker search alone, or splice head and tail into claimed continuity. Mixed media takes a different budget path.
