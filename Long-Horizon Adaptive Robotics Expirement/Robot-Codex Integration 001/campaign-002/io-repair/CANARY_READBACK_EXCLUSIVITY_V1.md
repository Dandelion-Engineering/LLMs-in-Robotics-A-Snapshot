# Prospective protected-canary JSON readback with exclusive writers

Declared 2026-09-29 before implementation. Smoke023's original failed assessment remains unchanged. `smoke-023-canary-diagnosis.json` (SHA256 `f21bfb3e4292a1eecfdaa194b81878ad938c636327688303471fb2f3e33df80a`) authenticates a complete 2,496-byte readback stdout, semantically equal to the retained 2,150-byte canary JSON with all45 true values. The native recipe redirects protected canary output, saves `$?`, reads the JSON in a Python heredoc, writes a separate execution sidecar, and prints the JSON with indentation. Existing recipes do not accept it.

## Missing proof and counterexample

An exact readback AST is insufficient. The final wrapper exit is the Python readback exit, not the protected canary child's exit. A model-writable sidecar is not independent exit attestation. A previously spawned writer could replace the note after a failed canary and before readback, then rewrite the sidecar; wrapper exit0, empty stderr and semantic equality could still hold. Initial input hashes omit restored notes, so absence from those hashes does not prove a fresh path. Do not implement a grammar-only acceptance change.

## Bounded proof

Add a separate optional helper. Preserve existing canary proof behavior and all45 fixed keys/true-value/schema requirements. The new class requires all of the following, otherwise it abstains:

1. Source-bound immutable interpreter/import namespace, protected canary, workspace construction, prior-stage retirement and note restoration. Authenticate the prior snapshot actually restored, not merely a terminal snapshot named by convention. Prove ordinary restored files/no aliases from the exact installer/restore code and inventories. Retained note and sidecar paths must be literal, normalized, distinct descendants of notes with no overlap/alias; authenticate their initial state from the complete setup plus restoration. Protected runtime mirror writers are confined to their unchanged live paths.
2. Authenticate the complete native executor/channel/process history from this fresh namespace's creation through the readback completion. Every command start must have one exact tool identity and complete authenticated stream/lifecycle. Account for nonzero exits too. No unmatched, hidden, redacted, unfinished, yielded, duplicated or unsupported execution is silently omitted. All other commands must finish before the canary recipe starts. Prior-stage processes must be independently retired; no command or surviving child may overlap the candidate interval.
3. Establish that preceding commands cannot leave another writer or change canary target/sidecar paths. Use a finite explicitly reviewed exact-script/AST allowlist, plus narrowly recognized literal read-only utilities and fixed protected robot status/query/history calls with distinct literal output paths. Do not infer purity by searching filenames, searching for suspicious words, trusting model text, or treating arbitrary Python as safe. Every permitted Python body is an exact reviewed AST with standard imports and read-only dataflow; no eval/exec, dynamic import, callback, user code, mutation, subprocess, background job or arbitrary write. Fixed protected robot-client source and transport must be pinned and establish no spawned persistent child. Any unrecognized earlier command rejects the new proof; the original proof paths remain available.
4. Recognize exactly the three shell steps: literal protected-canary redirect; immediate capture of `$?`; one Python heredoc receiving that shell variable. Permit only the declared reviewed AST dataflow: standard json/sys/Path imports, fixed target Path, `r=json.loads(p.read_text())`, a distinct sidecar write of the received integer and target path, and `print(json.dumps(r,indent=2))`. No mutation of r, target write in readback, alias, shadowed name, extra statement or alternate source. Require exact native argv/environment and source-bound imports, complete empty stderr, genuine integer-zero wrapper completion, unique process association and conservative chronology.
5. Under that exclusive-writer proof, the protected canary is the only possible producer of the newly redirected note during the interval. Complete actual readback stdout must parse without duplicate keys and equal the separately retained before/after note as a JSON value. Require the complete original schema, exact45 true checks and qualified:true. Retain source/capture/chronology/restore/prefix identities and semantic versus byte equality explicitly.

The proof establishes source-bound protected check values with an observed semantic JSON readback. It does not claim independently captured original redirected stdout bytes, an independently observed canary child exit, or model attention. The sidecar remains corroboration only. Empty-stderr gating still rejects simple redirection failures; exclusivity is additionally required and must never be replaced by that gate.
