# Evidence contract and review boundary

This prospective candidate is separate from Campaign 002. Development uses deterministic operator witnesses only. No model thread, inference, pilot, scored agent attempt or final campaign allocation is created. Qualification snapshots in `Architecture Map/releases/RCI001-C03-dev/` bind each attempt to its exact sources and unchanged inherited infrastructure. A later human review and final registration must precede model admission.

## A new task on the same hardware

`cell_c.py` adds one ordinary free rigid cuboid, its visible tag, and a noncontact destination marking. The cuboid copies A1's geometry, mass and contact parameters. The original scene, actuator parameters, limits, servo, physics timestep, camera pipeline and lower-level adapter are inherited. Removing the three declared additions produces the original XML. The pad uses a neutral gray marking so it cannot impersonate the colored C tag.

`ConventionalController` recognizes C completion from fresh public observations but contains no C motion. C transport, processing and inspection, and any high-level transport to C_pad, are rejected at native admission and planner entry. The protected geometric evaluator separately requires the full C footprint, resting height, speed, open jaws and arm clearance for one second. Neither controller claims nor a completed motion establish that acceptance.

Between C jobs the ordinary A/B transport skill performs public logistics jobs. The schedule contains at least three C jobs, with protected sampled intervening A/B jobs. Only the current order is released. The same running physics owner preserves arm and A/B state. Replacing C at its source is an explicit external-loader job-boundary event, recorded outside public history with its before/after truth. It is never available to the robot or used during a recovery.

The private deterministic motion witnesses are operator-only source/evidence. The runtime constructs its mount solely from `template/`, current public mirrors and persistent guest content. Neither the repository, this report, qualifiers, source snapshots, evaluator nor future schedule is mounted. Canary checks include real executor and Code Mode access denial, network denial, immutable instruction paths and fresh scratch/process boundaries. No developer motion sequence is seeded into guest notes or programs.

## Exact persistent workspace history

`journal_fs.py` is a protected FUSE filesystem, not a filesystem watcher. The kernel forwards file operations to a single serialized filesystem owner. Every successful content/path/metadata change follows durable content-object storage and a durable hash-chained delta. Direct I/O disables dirty page caching and writable mmap. Rename, replacement, hardlinks, symlinks, truncate, unlink, and writes through an unlinked open handle retain their exact intermediate states. Closed unlinked metadata is reclaimed; every old content object remains in the evidence store. The initial tree and final tree are explicit records. Unsupported special-file, extended-attribute and allocation mutations are denied. Kernel advisory locks are not file-content mutations.

Each record binds run, fresh session, exact development revision/snapshot hash, operation, Linux monotonic and wall clocks, predecessor hash, and state hashes. Where the kernel supplies a live caller, PID, process start ticks and PID namespace distinguish isolated-runtime processes from outer-runtime processes. A missing process identity remains explicitly unavailable; it must not be guessed. Framework checkpoints carry complete state hashes. Independent `verify_journal.py` reconstructs from deltas and verifies retained content, every read slice, chain order, state hashes and final closure.

The complete journal scope is `/workspace`: all persistent notes, programs and canonical continuity, plus trusted instruction/live-file versions. Each namespace has a new `/tmp`, process environment and memory. Those ephemeral process states are outside the persistent-workspace claim. Complete process memory, hidden model reasoning and hypothetical unseen information are not reconstructed. A FUSE/server crash, partial record, missing object, source mismatch or unclosed final journal invalidates the encounter; there is no silent server restart or automatic physical replay.

The limits are 256 MiB of live workspace/open-unlinked content, 16 MiB per file and 1 GiB of protected journal plus content objects per block. The original bounded host recorder, executor/Code Mode capture, action/observation budgets, durable admission and timing monitor remain. Each C encounter renews a 12 MB sparse-camera allowance; each activation renews its 50 explicit-image allowance. The host reserves that aggregate image capacity inside its unchanged 512 MiB evidence ceiling and checks a 100 GiB native free reserve plus 2 GiB retirement headroom. Journal pressure refuses further operations; a capture or transport failure closes admission and requires stopped/invalid accounting. Old evidence remains available. Final qualification audits exercise corruption, omission and quota failures separately from physical success.

## Images and observable behavior

The `robot_image` dynamic tool accepts only an explicit observation sequence in the bound thread/turn/session/epoch. It returns the actual protected PNG as an app-server `inputImage` item and a text identity receipt. No arbitrary host path or URL is accepted. Capture time, publication event, call identity, delivered image hash, Windows wall/QPC time and exact image bytes are retained. An image may be available without being requested or delivered. Delivery is interface evidence; it does not prove the model used the image correctly.

The development check invokes the exact app-server client dispatcher with a recorded RPC request and decodes the returned image bytes. Its request and response validate against the schemas generated offline by the pinned installed app-server binary. It also exercises a camera image from the running simulator through the same tool implementation. No model perception or reasoning is claimed; that would require the explicitly deferred model campaign.

The client retains public assistant messages and tool events, and the inherited executor/Code Mode relays retain public tool requests/results. Reasoning event types, reasoning fields and encrypted/private reasoning payloads are excluded before log serialization; raw provider events are disabled. Read availability, actual tool reads, tool results delivered to the app server and the model's visible response remain different evidence layers. The workspace contains a namespace-local gateway token; the real Windows robot capability never enters its version journal.

## Terminal continuity and clocks

Handback acceptance alone creates a pending receipt. A later actual conventional command admission under the new authority epoch establishes resumption. Only after the previous session's namespaces retire can `TerminalAppend` append a clearly machine-authored record to the Linux canonical backing file. It binds the accepted and resumption event IDs, request, run/session/epoch, simulation/wall times, evidence hashes and original/final content hashes. The entire preceding agent-authored byte prefix is preserved. The protected host mirror is then updated to those same bytes. The next session sees the same canonical file.

Rejected handback, no resumption, wrong identity, interrupted handback or incomplete retirement cannot produce a success append. A durable intent makes the append idempotent and reconciles interruption after replacement but before receipt publication. Conflicting bytes fail closed. Agent note commits remain bounded to 32 KiB; the canonical surface reserves up to 64 KiB for framework records, with each terminal suffix at most 4 KiB. An exhausted reserve stops rather than truncating earlier content.

Physics runs continuously on the inherited single owner while the supervisory thread performs durable I/O. Windows QPC timing retains every physics sample and applies the unchanged maximum-lag and one-second RTF gates. The workspace records Linux CLOCK_MONOTONIC separately. A warm fixed-socket relay avoids timing WSL startup as clock uncertainty. Each protected checkpoint records a Linux timestamp inside Windows before/after QPC+wall brackets bounded to 150 ms, with a contemporaneous simulation anchor when available. Replay must use these bounded intervals; it must not equate the two clocks or invent an exact common timestamp. Raw observations retain capture and publication identities. Plant truth is explicitly protected and separate from onboard evidence.

## Interpretation

Deterministic placement establishes apparatus reachability, not a model-created capability. Artifact existence alone establishes neither use nor transfer. The predeclared distinctions in [CONTRACT.md](CONTRACT.md) keep immediate task success, later content-bearing reuse, useful transfer, rediscovery, unknown behavior and optional durable procedures separate. Without a matched withholding intervention, the causal contribution of a retained artifact remains unknown. Three encounters in a block share a world and filesystem and are not independent samples.
