# Campaign 003 scored declaration rules

This tooling does not choose a sample size or authorize a launch. The complete independent live and three-encounter pilot gates must pass first. The allocation is then chosen once from actual pilot runtime, storage and failure evidence, recorded in `allocation.json` and frozen before any scored outcome.

The independent unit is a fresh persistent block. Each block declares exactly three C encounters separated by ordinary A/B work. Every C encounter uses a fresh Astra/max conversation and fresh process namespaces; only the block's permitted filesystem persists. Each block starts from the same qualified template, without qualification or pilot artifacts. Within-block encounters are correlated.

The successfully qualified source files, task geometry, physical/evaluator thresholds, sole bootstrap, model and memory strategy remain exact. The previously frozen 3600/4200/4500-second per-session envelope and approved 120 actions, 256 MiB native core and 2 GiB host evidence caps apply. All other observation, workspace, journal, timing, isolation, authority, capture, durability, retirement, memory and free-space constraints remain in force. Declaration and readback tools are operator-only.

A valid task failure ends its block; later C slots in that block are not run. Continue to the next predeclared independent block. An infrastructure-invalid or unknown attempt stops the campaign and leaves every remaining slot not run. A capacity admission failure stops admission; preserve all evidence and the reserve. There are no replacements, retries for a favorable outcome, limit extensions, adaptive sample sizes or within-campaign repairs to the frozen system.

Before each block, authenticate its immutable manifest, allocation membership, exact sources and pilot gate. Afterward require the original queue disposition and an independent evidence audit before admitting the next block. Record valid successes, valid task failures, infrastructure-invalid/unknown outcomes and not-run slots separately. Queue success alone is never qualification or task success.

Analysis keeps joint task success, created artifacts, content-bearing later reads/executes, concrete observed reuse, useful transfer, rediscovery and causal contribution separate. Useful transfer requires relevant prior content and valid later success. Causal contribution is unknown without a separately authorized withholding intervention. Hidden reasoning is excluded. Qualification and pilot evidence remain unscored.
