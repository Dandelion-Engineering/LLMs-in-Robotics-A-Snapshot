# Development workcell host

`supervisor.py` implements public journaling, command identity/authority, continuity commits, native command normalization and handback. `run_host.py` binds it to byte-verified frozen Runtime 004 classes on the protected host, provides loopback HTTP, and runs baseline/reference/development-server modes. `challenges.py` holds operator-only initial fixtures and reference recoveries. None of these files belongs in Robot-Codex's permitted filesystem.

The gateway rechecks each request's authenticated epoch after queueing, including note writes, and rotates capabilities immediately after an authority transition. Session10 adds a protected launcher-to-host lifecycle bridge with a separate operator token retained only outside the runtime, single-use invocation identities, durable start/retire/stop receipts, cancellation and successor fencing. Old queued calls and newly issued old-token calls are denied. Handback revokes robot access; a late launcher retirement after handback preserves resumed conventional motion. The trusted broker must bind one robot token per namespace and never reload successor credentials. The host does not itself create or destroy that namespace.

These changes follow the four original native fixture attempts; their immutable source snapshots and results remain the evidence for those physical runs. [Session10 host verification](session10-verification/README.md) uses synthetic state and actual loopback HTTP, without creating a physical Cell or invoking a model. Physical and actual-model readiness evidence belongs to the separately registered Session10 runs. See [API](API.md) for exact lifecycle and public camera/continuity routes.

Two implemented families use the existing physical scene and skills: healthy raw stock placed in quarantine (one required A part), and a raw workpiece occupying insert A's return home while a B job requires setup (two parts, one B required). The latter requires moving the blocker and completing setup before handback because the frozen baseline retains failure counts. Initial placement modifies free-joint poses only before episode timing; recovery never sets object state. The controller and simulator sources are imported unchanged and checked against the r4 artifact index.

Ordinary tabletop displacement is not a novel fixture: the frozen detector labels points outside named pads as `raw`. The new fixtures use existing excluded named pads. A fault-reset family is deferred because the simulator has no reset interface.

The reference is not proof until its queued run completes and shows physical actions, fresh public effects, accepted handback and useful resumed conventional work. Failures remain results. Reference plans, fixture identities, protected evaluator output, and manifests never enter public runtime files. The public episode identity is opaque.

Require queue `state=succeeded` and `exit_status=0` before consuming completed outputs. Exit zero means the bounded host produced an honest terminal report, not task success; inspect `result.json`. A failed reference is preserved, not silently retried. `baseline` stops when the frozen controller itself requests assistance; it gets its existing bounded retry logic first. `reference` then uses the protected reference actions through the same gateway, observes them, hands back and waits for the independent evaluator. `serve` exposes the API and never launches a model itself; source/model verification and agent lifecycle are separate launcher responsibilities.

The native recorder reuses the separately versioned sustainable `FutureEvidence` backend, with drift-safe full-precision 100 Hz joint/TCP/effort motion, a live image ring with sparse two-second persistence, 50 MB core and 12 MB image quotas. Live sensing remains 10 Hz with no full-stream PNG/depth persistence. Authoritative public history and registry are separate, fsynced before action; runtime files mirror this public history. All observations/actions are retained as small structured records. Explicit overhead image requests retain at most 50 images. The default aggregate cap is 200 MiB. A registered `serve` manifest may declare up to 512 MiB and up to 1800 simulation/wall seconds for bounded model qualification; reference/baseline maximums remain unchanged. The cap covers protected evidence plus runtime `live/`; individual writer budgets reserve headroom. These runs retain timing lag rather than asserting production real-time performance. Recorder source hashes are saved independently and can be required through manifest `recorder_source_sha256`.

World time is wall-paced and never deliberately stopped while the agent reasons. Synchronous JSON/fsync and sparse image compression can add measured lag; no conclusion about responsiveness follows from an unqualified development host. The existing low-level limits are not a whole-arm collision safety certificate. The host exposes no program-execution service; externally qualified namespace shell programs retain only the same bounded gateway authority. Complete supervisor crash recovery is not implemented. See [API](API.md) for the exact callable surface and limits.

The first Session10 physical smoke stopped before model startup when a concurrent Windows reader briefly denied atomic replacement of a public observation mirror. Its failure evidence remains unchanged. The launcher now obtains live mirrors through authenticated HTTP; the host additionally retries only `os.replace` Windows access/sharing/lock denials (WinError 5, 32, 33), at most four waits totaling 75 ms. It preserves the fsynced stage and old destination, never deletes files or changes permissions, and propagates persistent or other I/O failures. `result.json.atomic_replace_retry` records retry/exhaustion counters and requested waits; physical timing lag includes any delay. The actual Windows reader-handle regression and fault-injection results are retained in [windows-sharing-001](session10-verification/windows-sharing-001/result.json).
