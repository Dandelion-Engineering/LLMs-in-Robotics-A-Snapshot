## Operational bounds and reproduction

The protected host owns physics and authority. It grants 20 action and 50 explicit observation requests per activation, preserved across invocation restart. The smoke allowed two model turns, each at most 600 seconds, within 1500 simulation / 1800 wall seconds. The pilot permits one 600-second model turn, up to 150 seconds of conventional follow-through, and 900 simulation / 1100 wall seconds. Both host manifests cap storage at 512 MiB. Physics continues during inference; measured clock lag is retained rather than assuming real-time equivalence.

The convenience program runner seals at most 64 KiB of source, fsyncs an admission before process creation, bounds wall time to 60 seconds and combined output to 1 MiB, and limits each child to 512 MiB address space, 8 MiB file size, 128 descriptors and 60 CPU seconds. It retires detached descendants. An admission without a final result remains unknown. Ordinary namespace shell access remains available with the same protected robot permissions; the runner is not an additional OS boundary or aggregate resource governor.

See [boundary implementation](boundary/README.md), [assessment methods](assessment/README.md), [registration commands](registration/README.md) and [protected API](../host/API.md). New attempts must use new immutable IDs, verify frozen sources immediately before queue submission, and be assessed only after official `succeeded` / exit 0. Failed queue attempts remain infrastructure diagnostics. These reproduction instructions grant no additional run authorization.
