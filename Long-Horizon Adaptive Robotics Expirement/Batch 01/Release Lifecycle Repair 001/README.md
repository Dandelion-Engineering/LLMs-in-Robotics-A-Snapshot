# Proposed model timeout lifecycle repair — staging only

The retained r3 C20/rep1/A2/persistent incident reported an absent owned model PID while the last completed resource sample still identified PID27772. `LocalModel.complete` stops its owned server on the fixed request timeout; `stop` clears `process` before waiting. The supervisor previously treated any missing current PID as infrastructure failure before collecting that request's error. This repair separates that intentional timeout transition from unexplained model loss. It does not reinterpret the old canonical result or authorize continuation.

Only `staging/` contains executable changes. `original-source-references.json` preserves hashes of the four copied original files. `change-inventory.json` gives the exact original/staged identities and allowed prospective Runtime delta. No original Runtime, frozen release, policy, prompt, model, task, physical controller, or calibration artifact has been edited here.

The model adapter publishes a frozen `ModelRequestTimeout` under a short lifecycle lock before clearing its process reference. The snapshot retains owned PID, timeout request identity, monotonic publication/deadline, shutdown state, and teardown errors. Process waits and HTTP calls never hold this lock. A process already observed exited cannot acquire an authorized timeout cause. Waiting for a busy request slot still does not kill somebody else's request. A timed-out adapter cannot restart its model.

The supervisor observes this state while the request future is unfinished. It first checks actual resource evidence, then terminates with prospective `model_request_timeout`, a valid policy-budget failure when evaluation authorization and the other validity gates pass. It emits the cause with the original request event. It detaches the future before any collection that can raise, so cleanup records exactly one failed call and one unknown token count. No response is delivered after this terminal decision.

All 30-second request, 1024-token output, 16384-token context, process, memory, and GPU limits stay unchanged. There is no model restart, extra observation grace, or policy fallback. `RESOURCE_POLICY` becomes version004 to disclose the changed lifecycle interpretation. Actual cap breaches, stale or missing overall observations, missing harness/GPU data, conflicting PIDs, spontaneous server exit, and failed teardown remain infrastructure failures. Only a missing private-commit value for the same retained PID in a sample beginning after a completed, trusted timeout stop has no active-model measurement requirement. Nonfinite values and numeric cap excesses are never exempted.

The existing sampler records a whole-sample start, not the exact model-read time. A sample that begins before timeout and reads the model after termination may conservatively remain invalid if its model measurement is absent. This repair does not invent capture provenance or excuse a pre-timeout missing measurement. The incident's retained sample had a finite below-cap value and matching owned PID, so it is covered directly.

A timeout published before a prospective independent completion landmark prevents spurious success. A timeout first occurring after independent completion or the episode cap is recorded during cleanup without replacing that settled outcome. Teardown/evidence failures remain separately capable of invalidating a run. The cause's observed time is the adapter's timeout publication, not a claim about when a remote server stopped computation.

Prepared deterministic tests use fake HTTP, process and cell objects. An event blocks termination while another thread requests a snapshot; the test verifies nonblocking access and both watchdog/future orderings. Supervisor fixtures check one accounting entry, no model-response delivery, valid budget-failure classification, late cleanup boundaries, and timeout-before-completion. Negative controls cover spontaneous exit, failed termination, unexplained PID loss, pre-timeout missing data, stale/missing samples, and unchanged caps. Existing model/supervisor tests are copied as regression coverage.
