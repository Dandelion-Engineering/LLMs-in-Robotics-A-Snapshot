# Minimal protected qualification and absence wiring

Proposal only, based on read-only inspection of `Runtime/protocol.py`, `release_runner.py`, `freeze_artifacts.py` and `experiment.py`. Implemented for review in `calibration_loader.py` and the separate `runtime-loader-integration.patch`; Runtime remains untouched by this subtask. No new qualification artifact, numerical bound or additional readiness gate is made here. Reuse the existing `disturbance_admissibility` evidence boundary.

## Existing connection points

- `protocol.validate_release_gates` verifies the timezone-qualified freeze time, existing readiness gates, and bytes of readiness references before concealed manifest creation.
- `release_runner.reference` verifies a `{path, sha256}` file reference. `verify_artifacts` deliberately requires exactly the three code/environment/model indexes; do not add a fourth artifact role just for restart evidence.
- `verify_release` returns the verified freeze and artifacts. `VerifiedEvaluationContext.artifacts_json` already carries protected serialized data from the gated authorizer into `experiment.run_episode`; it need not be sent through candidate IPC or included in candidate state.
- `run_episode` currently sets `restart_calibration=None`, captures/classifies at `restart_begin`, then calls `cell.cancel` and submits `restart_worker`. The `pending_type == 'restart'` branch emits `restart_ready` after the replacement worker's ready response is available. There is currently no explicit paired wall/simulation absence record.

## Bundle input without broadening authority

1. Add an explicit `freeze.restart_qualification` reference only for `restart_matching_mode: qualified_class`. Keep the ordinary byte `sha256` for file integrity distinct from canonical `bundle_sha256` and `class_spec_sha256`; they are not interchangeable. Freeze `selection_rule: unique_bilateral_payload_template` and a `payload_template_to_cell` mapping with one measured cell per supported `kind:family` (for example, separate `part:A` and `part:B` cells sharing one fixed destination). Also freeze `prospective_absence_bound_s`, `absence_timebase` (`simulation` or `wall`) and `absence_endpoint` (`restart_ready` or `recover_held_admitted`). These support values come from physical qualification, not this plan. Legacy exact-configuration releases retain their separate mode.
2. Store the bundle plus an artifact-ID-to-file-reference index outside candidate state. The bundle supplies its existing class specification, measured cells, measured point references, prior acceptance time and empirical-transfer rule. Use the existing reference verifier to check every referenced artifact byte before declaring `bytes_verified_by_operator` or creating `verified_artifacts`. Missing files, duplicate artifact IDs, changed hashes, post-freeze evidence or an unsupported requested cell are not usable qualification.
3. Perform these qualification structural/reference checks in the existing pre-seed release validation, and reverify them in `verify_release`. This prevents a seed-generating release from silently deferring an absent qualification to runtime. It adds no new experiment gate or trial quota. The existing readiness decision must still be based on actual physical evidence.
4. Include the verified bundle and independently frozen expectations in protected `artifacts_json`, for example under `restart_qualification`. Expose a copying accessor on `VerifiedEvaluationContext`; keep its existing authority check and exact episode arguments. Do not accept an arbitrary candidate-supplied dictionary or reload a changing path during an episode.
5. At initialization, validate every mapped cell and prepare its exact grip/route pair with `match_mode: qualified_class`, matching `qualification_cell_id`, role, source hashes, evidence references and measured envelope. At the unchanged existing cut, select only the frozen mapping for the snapshot's unique bilateral held payload, using its source-bound template identity. Unsupported templates, ambiguous holds or mismatched observations stay unknown. This is evidence assessment: it does not choose a candidate action, cut time or destination. A failed physical predicate cannot trigger a search for a more favorable cell. Pass that single pair and `qualification_context` to `classify_restart`. Development probes can pass a `VerifiedRestartQualification` issued by the same protected loader without constructing evaluation authorization or drawing evaluation seeds; arbitrary dictionaries are refused.

Bundle byte verification belongs before the episode starts, outside the physics-owner cut path. Class/domain compatibility remains separate from the existing actual grip/route/obstruction predicates. Adding helper files to Runtime means the next ordinary code index/ZIP already includes them automatically.

## Explicit absence record at restart-ready

Keep four landmarks, using `time.perf_counter()` for wall durations and fresh `float(cell.data.time)` for simulation durations:

- Capture start and finish, so protected capture/classification overhead is visible separately.
- Authority revocation immediately around `cell.cancel`; take the conservative start timestamp just before the call. The earlier `restart_begin` emission is not an exact cancellation timestamp.
- Replacement worker readiness, sampled in the existing `pending_type == 'restart'` branch immediately before emitting `restart_ready`.
- First novel admitted post-restart nonpassive action, if the measured qualification scope includes sensing/reconciliation and guarded holding after worker readiness. Only `recover_held` to the frozen destination matches that measured route; another control/destination ends this opportunity with unsupported scope. A later action cannot repair it.

Add `restart_authority_revoked` with `before_cancel`/`after_cancel` landmarks, then `restart_absence` with paired clocks/durations and independently qualified coverage. Embed the ready observation in `restart_ready` too. Link them to the original restart event and frozen qualification identity. Apply `actual_absence_coverage` only in the same timebase and to the same endpoint used by the measured bound; retain both clocks rather than mixing or relabeling them. The physical hold interval normally concerns simulation time, while wall duration is the operational restart/timing fact; the eventual physical qualification must state the actual convention.

`restart_ready` means the process is ready, not that fresh sensing, reconciliation or a recovery command has occurred. If the supported absence ends at first admitted recovery/control, readiness supplies an intermediate lower bound and coverage remains pending until that endpoint. Record a separate final interval then. A longer interval cannot inherit coverage from the shorter restart-ready interval.

Preserve the initial at-cut assessment exactly as recorded. Append duration coverage as a later observed fact; do not rewrite prior evidence using eventual task success. If restart fails, the episode times out, or no qualifying action is admitted, record the endpoint as unobserved with the observed elapsed lower bound. Do not encode a missing endpoint as zero absence. An exceeded/unknown duration makes that recovery exposure unsupported for that qualification; it does not alone authorize discarding the task result or excluding a paired block.

## Retained identity and offline verification

`restart_begin` retains `restart_qualification_identity`, the selected mapping assessment, the exact calibration pair, and capture/classification landmarks. Identity includes the actual freeze file path/byte hash, bundle file path/byte hash, bundle/class canonical hashes, frozen mapping/rule, and every artifact ID/path/byte hash. The ordinary run manifest already retains all Runtime source hashes, including capture, classifier and loader code. None of this enters candidate packets or filesystem state.

The existing Investigation reader verifies snapshot/hash and the recorded required-predicate aggregate; it does not currently recompute the classifier. Its owner is preparing explicit qualified-mode verification. The reader must bind the freeze file hash to independently verified run/release authority, then re-read those retained bytes and call `load_restart_qualification(freeze, freeze_path)`. The loader rehashes bundle and evidence files; embedded `bytes_verified_by_operator` booleans, context dictionaries and event paths alone are not independent authority. Missing/mismatched retained input stays unknown.

Next call `select_restart_calibration(verified.as_dict(), snapshot)` and recompute `classify_restart(snapshot, calibration=selection['calibration'], qualification_context=verified.as_dict()['qualification_context'])`; compare the recorded pair/mapping/assessment with the independently reconstructed result. Do not change the original at-cut record. Recompute absence from the revocation and endpoint landmarks using the verified `absence` settings, rather than trusting an embedded `coverage: pass`. Qualified recovery eligibility requires both the at-cut physical assessment and actual supported absence. Missing/exceeded duration cannot retain recovery eligibility merely because the at-cut record said admissible.

`absence_observation` returns schema `restart-absence-observation-1`, original `start`/`end` landmarks, `wall_duration_s`, `simulation_duration_s`, `observed_endpoint`, explicit qualified clock/endpoint, `coverage`, and `physical_recovery_success: not_assessed`. When readiness precedes the required recovery admission, coverage is unknown with `observed_elapsed_lower_bound_s` and a separate elapsed-bound check. `other_control_admitted` or `episode_end_unobserved` cannot claim the requested recovery endpoint. The integration appends all records to `restart_exposure.absence_observations` as well as protected events.

Prospective trigger alignment remains the physical-fixture owner's work: the actual episode uses TCP z >= 0.08 m, while the older primitive used object-center z > 0.075 m. This loader does not equate those cuts, move the cut, or manufacture a shared measured cell.
