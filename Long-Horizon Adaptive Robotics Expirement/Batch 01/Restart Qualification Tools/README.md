# Protected restart-class compatibility and measured qualification

## Implemented protected exporter and proposed integration

`descriptor.py` now supplies the source-bound exporter that the original design below identified as missing. `qualification.py` checks an independently frozen, artifact-verified measured carry cell and its explicit absence support. `runtime-integration.patch` supplies opt-in Runtime hooks; the root task owns its application and subsequent Runtime/physical checks. See [Integration](INTEGRATION.md) for the exact boundary and [Wiring plan](WIRING.md) for the proposed protected loader and absence measurements. No measured recovery qualification, numerical grip/route bounds, readiness pass or evaluation seeds have been created by these tools. The older sections below remain design rationale; their statement that no Runtime patch is included is superseded by the delivered patch.

The separate `calibration_loader.py` and `runtime-loader-integration.patch` now implement that wiring proposal: protected file-byte verification, frozen A/B payload-template-to-cell mapping, same-cell grip/route evidence, explicit revocation/readiness/recovery clocks, censored endpoints, and provenance for independent offline reconstruction. Fourteen synthetic loader/integration tests pass; the patch remains unapplied. Actual qualified recovery eligibility additionally requires supported observed absence; an at-cut admissible report cannot cover a missing or exceeded interval.

[Construction](CONSTRUCTION.md) defines the non-authorizing path from the completed recovery-screen extraction to a provisional limited empirical cell and untouched validation. `bundle_construction.py` retains every trial and exact coupled states, produces an intentionally incomplete draft, and never fits bounds from successful marginal extrema. The coordinated fixture addition accumulates whole-arm/payload outer boxes at every native physics tick, retaining discrete sampling scope rather than asserting a continuous proof. Four synthetic construction tests pass; no pending physical outputs were inspected.

Both queued compiled-model probes passed all descriptor and mutation checks at 3/6/10 parts, with unchanged source bindings and official succeeded/exit-0 receipts. Across nine exports per probe, the original Python loop took 0.252228–0.269132 s; the vectorized check took 0.023764–0.025152 s (median 0.255106 → 0.024014 s, about 10.6× faster). This is compiled-model compatibility and isolated export timing only: no physics, renderers, candidate inference, held recovery or readiness test ran. Summary and receipt links are retained in [Integration](INTEGRATION.md) and `validation.json`.

This folder is outside the Runtime/Calibration Tools source hold. `compatibility.py` and its 19 synthetic tests use only the standard library. They do not load a simulator, generate a seed, read calibration artifacts, run a robot, set readiness or modify another file. The descriptor and fixture examples in the tests are synthetic, never calibration authorizations.

## Integration API and trust boundary

```python
assessment = verify_class_compatibility(
    frozen_class_spec,
    protected_compiled_observation,
    frozen_spec_sha256=release_freeze["restart_physical_class_sha256"],
)
```

The result's `compatibility_state` is `pass`, `fail` or `unknown`. Exact scene/configuration hashes are retained, but equality of those instance hashes across seeds or populations is not required. The function checks the independently supplied frozen class digest, exact causal source/component identities, declared 3/6/10 population membership, full semantic entity inventory, both families and inserts, template identities, sampled main-geom mass/friction, fixed friction components, and actual compiled mass/COM/full inertia. It independently computes the latter from the frozen axis-aligned box construction, including the tag and process-mark masses. Rotated/mixed primitive mass construction is unsupported and remains unknown. Numeric comparison tolerances concern compiled representation roundoff only, not physical safety margins.

This is deliberately **compatibility only**. `recovery_admissibility` is `not_assessed`, `instance_previously_calibrated` is unknown, and all effect flags are false. A successful result cannot make a free pad a safe route, prove a grip, admit a cut, reveal hidden information, select a new seed or exclude a block. No current safety predicate or threshold is changed.

The missing integration is a protected, source-bound **descriptor exporter**. Its component hashes must be calculated from actual compiled data and exact assets/settings, not copied from the expected class. The required inventory covers robot geometry/joints, native actuators, static geometry, contact/solver/integration settings, recovery controller, sensor/registry semantics and canonicalization rules. Every relevant nonvarying field belongs to one component or entity template; an explicit whitelist permits only sampled main mass/sliding friction, legal population expansion, public-generator layout/visual variation and consequent derived mass properties. Unknown differences must fail validation. Preserve names rather than array indices when population changes. Keep exact XML/configuration hashes alongside the normalized representation.

The exporter supplies per-object `compiled_mass_properties`: mass, COM in body coordinates, and the full body-coordinate inertia tensor. MuJoCo's principal inertia plus inertial-frame quaternion must be transformed into that tensor; do not compare only eigenvalues or ignore COM/tag offsets. It must derive template identities from the observed compiled entity fields, not just a claimed family label. Its initial layout/visual-domain validation and existing `initial_world_report` remain separate prerequisites. This module cannot detect a dishonest or incomplete exporter by inspecting a self-reported digest. That boundary is explicit and must be covered by exporter counterexamples before integration.

Use this as a new explicit calibration `match_mode: qualified_class` inside the identity stage of `_calibration`. Preserve the old `exact_configuration` mode and all existing prior-artifact/source/envelope checks. Never substitute compatibility for `_grip`, `_route`, contact/support, phase/lease/device, freshness or finite-capacity checks. A verified prior qualification entry must reference the frozen class digest and an explicit prefreeze empirical-transfer rule. Missing exporter evidence, prior qualification or measured state bounds keeps classification unknown. Class mismatches are recorded as compatibility contradictions; their infrastructure/candidate cause remains separately adjudicated. Do not automatically convert a descriptor mismatch into a candidate failure or exclusion.

## Smallest useful measured scope

The minimal useful qualification unit is **one workpiece physical template, one observed source/carry-state cell, one absence bound, and one shared `recover_held` route to one destination**. It is not every raw slot, every candidate trajectory, every buffer or the entire contact workspace. The earlier proposed 20-trajectory screen is not an automatic requirement.

For that unit, the necessary evidence is:

1. A successful physical pickup with actual bilateral load-bearing contact at the declared cut, full pre-cut snapshot, and unchanged physical dynamics during the declared absence.
2. The full recovery trace and independently verified final containment, open empty gripper and settled terminal state. A receipt or final success alone supplies no measured initial grip/route envelope.
3. Supported bounds for jaw width, relative payload pose/rotation, each finger's force, payload and joint/finger velocities, payload-bottom clearance and route-start configuration. Retain correlated cells; do not combine unrelated marginal extrema into a larger supposedly measured box.
4. A conservative arm-and-payload sweep/clearance representation, with its sampling/error allowance, checked against the actual other bodies and exact destination. The current classifier only compares supplied corridors; it does not establish that TCP boxes cover the arm.
5. A frozen empirical-transfer rule supported by finite development variation and a separate development validation after the tentative limits are fixed. This supports conditional use in unseen class members; it does not convert the public parameter range into a measured continuous interval.

Reuse successful source-matched measurements already collected where they cover these facts. A repeat is needed when the causal controller/geometry changes; the new HOME joint-0 value therefore needs the new physical evidence. An artifact whose only changed source file is unrelated still needs an explicit causal identity/provenance mapping, not blanket acceptance of mismatched source hashes.

To extend across the full public mass/friction domain, a small targeted next screen can cover the four mass/friction endpoint combinations and an independent interior development validation, using only the selected state/route unit. It is a finite empirical screen, not a five-trial certification. Reuse covered points; add only the missing combinations revealed by failures or a broader proposed claim. Do not assume maximum mass/minimum friction is the unique worst case. Boundary construction occurs before model initialization and uses retained exact settings, never searched concealed seeds or state teleports. Validation can use a larger population/crowded layout to test the actual route-resource interaction, avoiding a blind Cartesian multiplication by all population counts and every family label.

Equivalent A/B physical templates may share an explicitly declared mechanical transfer argument, while their sensing/identity evidence remains separate. More parts do not automatically require a new model class: verify every instance/template and all actual body/corridor/resource predicates. Conversely, an untested crowded route is not proved by an empty pad or a population-membership pass. If the finite evidence does not support a broader transfer claim, keep that part of the scope unknown. This still permits honest classification of measured-scope events and complete paired task evaluation; it does not justify calling every configured restart admissible.

Unresolved numerical bounds are the measured grip/pose/force/velocity cell, payload-bottom minimum, joint/finger start ranges, conservative swept regions, and absence duration. The existing one-second authority-cut probe does not cover a longer real candidate-process restart. Record the actual restart/reconciliation time and qualify a bounded interval with margin from measurements; assessment at the cut is conditional on that bound, with actual duration coverage recorded afterward independently of task success. A low-clearance A3 carry outside the measured cell remains unknown rather than inheriting a higher carry's envelope. Active cycle/inspection timer survival is also unqualified until separately evidenced.

After qualification and freeze, generate concealed manifests once and apply the same prospective checks to all entrants/conditions. Do not rehearse concealed seeds, postpone a cut to make one entrant's state easier, or use eventual success as calibration. Retain configured opportunity, actual exposure, compatibility, admissibility and recovery progress separately. Unknown/inadmissible exposures remain visible; task success denominators and paired persistence contrasts are not silently filtered to the easiest recovery states.

## Resource gate: precise current meaning and missingness gap

The reviewed sources are bound in `source_review.json`. `model_runtime.py` declares a Windows Job process-memory limit, process count and core affinity. Its CUDA model/KV/compute-buffer report is a startup allocation-target check, explicitly not a hard VRAM allocator. Candidate restrictions are separately declared by `candidate_worker.py` and `sandbox.py`. `experiment.py` adds sampled stop thresholds for harness RSS, model private commit and whole-device GPU memory; device totals are not candidate-attributed usage.

Do **not** flip `resource_caps_enforced=False` to imply every budget is continuously hard-enforced. A source-bound typed policy can truthfully satisfy the experiment's `timing_and_resources` readiness gate after measured validation: name each hard limit and scope, each startup buffer check, each sampled watchdog threshold, sampling/freshness conditions and actual stop behavior. Use a readiness statement such as `declared_resource_policy_operational`, with evidence references. This requires no nonexistent hard VRAM allocator. It also does not yet establish the original RAM/GPU budget numerics: freeze any calibrated departures openly and consistently.

Concrete current gap: ResourceSampler defaults to a 5 s period and a 2 s GPU query timeout; supervisor checks its cached `latest()` every 0.25 s. That is a poll interval, not a 0.25 s observation/detection bound. `resource_breaches(None)` returns no breaches. Missing/nonfinite RSS/commit/GPU values are skipped, and the loop does not check sample age. A fatal sampler-thread exception becomes a cleanup error and infrastructure-invalid result, but per-metric API failure is retained as `missing_reason` without necessarily failing the thread. Repeated missing GPU values can therefore pass without a watchdog stop.

Minimal correction before claiming that sampled policy operational: require the metrics relevant to this episode (baseline has no model process), retain each capture start/finish/age, and give missing/stale data an explicit bounded treatment. Before the episode clock, wait asynchronously for one complete fresh required sample within a declared startup cap, or record an infrastructure prerequisite failure. During the episode, allow only a frozen measured grace interval for a transient failed read; after it, stop with resource-evidence-unavailable infrastructure classification and apply the paired-block rule. Immediate known over-limit samples still stop normally. Never replace missing values with zero or attribute a whole-GPU overage to the candidate.

Choose the freshness/grace bound from actual sample duration/gaps plus bounded supervisor polling allowance; do not invent a subsecond guarantee from this five-second sampler. Test missing-first-sample, GPU timeout/missing metric, frozen cached sample and healthy fresh samples with synthetic inputs, then retain actual live sampling/stop evidence. Continue to disclose between-sample peaks and separately timed Linux/Windows memory observations. Current source semantics plus pending physical/resource measurements do not by themselves pass this gate. No Runtime patch is included here.
