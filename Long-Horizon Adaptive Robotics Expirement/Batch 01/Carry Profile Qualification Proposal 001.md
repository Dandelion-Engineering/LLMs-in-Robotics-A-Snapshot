# Fresh raw-pickup carry support — proposal 001

Status: source-only proposal, 2026-09-23. No execution, qualification, selected numerical envelopes or Runtime changes. Existing P1 rules, accepted bundle, source files, development outcomes and failures remain unchanged. No scored seeds have been created or inspected for this proposal.

## Smallest useful scope

One new **raw A1→fixture, clearance 0.25 m, speed scale 1.0, vertical, no avoid zones** construction and validation cell can be frozen commonly for all entrants. This matches the first A3-003 action retained by the completed original-cut diagnostic. It establishes a limited common recovery opportunity if the measurements and validation pass; it does not establish that conventional carry, every A3 output, other source slots, B2, or the permitted continuous objective range is covered. Outside states remain unknown. This single-cell option requires no multi-cell Runtime selector.

The [qualification plan](Restart%20Calibration%20Qualification%20Plan.md) expressly permits supported local cells and unknown unmatched states. Its readiness statement does not require every future trajectory to be admissible. Therefore a single representative profile is sufficient for that limited prerequisite scope. It cannot support a statement that conventional raw pickup is calibrated: the conventional profile is raw→fixture at 0.16/0.8, whereas the original screen used raw→inspection at the defaults. Measure conventional raw→fixture separately if baseline carry coverage is part of the claimed prerequisite. Preserve different admissibility denominators; do not change task outcomes or discard original failures.

Recommended finite core: qualify the representative A3 profile first under the existing one-cell schema. Declare the conventional profile separately as the next coverage check. If its start states fall outside the selected cell, retain that result and either accept the limited scope or undertake a separately versioned multi-cell extension. Do not make support universal by joining unrelated extrema. The low-clearance/slow corner 0.08/0.3 may remain explicitly unsupported; its optional screen below is prospectively specified so it can expose objective coupling without changing A3 policy parameters.

## Why the old cell does not answer this question

The completed A3-003 and A3-004 small results report successful tasks and passing timing, but inadmissible carry cuts: `measured_recovery_route` fails `joint_start` and `joint_velocity` while its other checks and the grip predicate pass. The exact A3-003 action excerpt identifies raw A1→fixture at 0.25/1.0. These observations motivate new shared development support; they do not repair the original classifications. Exact numerical q/qd deviations are not inferred here.

[cell.py](../Runtime/cell.py) `plan_transport` accepts clearance 0.08–0.25 and speed 0.3–1.0, with defaults 0.16/0.8. Destination height and clearance change the lift path; subdivision/IK continuation and speed affect joint state at the same public TCP threshold. A TCP-height match alone does not imply a joint-position/velocity match. The old [run_screen.py](Recovery%20Qualification/run_screen.py) submits `destination='inspection'` and also waits for protected grip/clearance conditions after reaching the public phase/height condition. It is not a reproduction of the first runtime public opportunity.

The new driver must cut at the **first selected transport's public phase 4/5, width <0.065 m and TCP z≥0.08 m observation**, before consulting protected grip or route predicates. Capture and assess those predicates independently; retain missed opportunities, unsafe/unheld starts and failed recoveries. Do not wait for a better q/qd or stronger grip. Use the same observation cadence as the runtime supervisor, or explicitly retain a timing difference rather than claim exact trigger equivalence.

## Existing-schema and execution constraints

The bundle may contain many cells, but that is not multi-cell selection. All mapped cells share one recovery destination. A single new `part:A` cell fits; unsupported templates remain unknown.
* [restart_qualification.py](../Runtime/restart_qualification.py) and [restart_state.py](../Runtime/restart_state.py): grip and route must name the same cell and match its exact envelope. Implement a **separate versioned profile driver and declaration** if adopted, retaining the source archive, queue identity, child containment and event contracts. Reuse unchanged physical/measurement utilities rather than monkeypatch the old plan or trial body.

## Only if separate cells must both be active

A minimal versioned extension would freeze a list of permitted cells per template and a **predeclared exact numeric selector** over cut-state coordinates. Select only when exactly one cell's selector contains the finite cut state: zero matches→unknown; multiple matches→unknown. No nearest cell, first match, trying cells until a predicate passes, entrant identity, eventual outcome or resampling the cut. After selection, use the unchanged full grip/route/class/absence checks. Cell selector regions and the full common rule must be fixed before fresh validation; validate uniqueness at the original cuts as well as each cell's physical support.

That extension touches frozen loader identity/calibration payloads, provisional-rule validation/launch binding, assessment membership, assembly mapping and the independently verifying reader. The current one-cell assessment cannot establish a new selector's uniqueness by itself. Keep the old public rule/version readable and all old artifacts intact. Any physical-class source change requires its own fresh source binding; do not relabel old measured cells with a new class. This work is **not needed** for the single representative common cell, and no mapper is implemented or authorized by this proposal.
