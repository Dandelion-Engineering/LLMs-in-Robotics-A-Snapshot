# Batch 01 continuity extraction rules

Rubric ID: `b01-continuity-rubric-1`. Written before the evaluation freeze; include this file's exact hash in the selected analysis artifacts. Changes after any scored result require a new analysis version and a stated sensitivity analysis, never silent relabeling. This rubric operationalizes the existing [evaluation definitions](../Long-Horizon%20Adaptive%20Robotics%20Experiment%20Design/Evaluation.md). It does not declare readiness or claim the extraction is already implemented and validated.

The target contrast is the same frozen candidate with private filesystem persistence enabled versus removed at restart. Current orders, public machine state, frozen knowledge and bounded command receipts remain available in both conditions. Compare both interrupted and matched uninterrupted cases. A different postrestart algorithm or compensating memory channel must be declared; it cannot silently become a pure persistence ablation. The 264-run matrix remains unchanged.

## Inputs, provenance and clocks

Use the protected immutable `manifest.json`, `result.json`, `events.jsonl` and `motion.jsonl`, their SHA-256 references, exact frozen source/configuration and release/queue records. Derived annotations are operator-only outputs. They never flow back into candidate memory, prompts or evaluation selection. Keep original results unchanged. A failed hash, incomplete event chain or ambiguous identity is an integrity finding, not permission to reconstruct plausible events.

The current event envelope is `robot-evidence-1.0`: `run_id`, sequential `event_id`, `event_type`, `source`, `sim_time_s`, `sim_tick`, `wall_elapsed_s`, `parent_ids`, `payload_sha256` and `payload`. Respect the episode clock origin; initialization/resource offsets are not task time. A physical service event's nested `payload.sim_time` identifies its effective simulation time; the outer event time can be its later logging time. Report both simulation and wall latency when actual endpoints exist. Never convert a simulation dispatch timestamp into measured wall actuation time.

Link by event IDs, request IDs, order versions, runtime incarnations, observation sequences and cycle/inspection IDs. Temporal proximity alone is insufficient to match two commands. Protected `world_snapshot`/`final_world` state, physical service histories and independent evaluator outcomes can verify effects; candidate claims cannot. If snapshots bracket rather than timestamp an effect, retain lower/upper latency bounds and sample coverage instead of inventing an exact onset.

## One row per planned opportunity

Create one operator annotation row per manifest-defined disturbance or cut opportunity. Keep planned opportunities that were never reached. At minimum retain: rubric/source hashes, run/case/replicate/condition, opportunity ID/type, paired-block ID, planned trigger, actual exposure event IDs and clocks, admissibility/basis, order/incarnation before and after, relevant part/resource/request IDs, each landmark below, contradictory/duplicate request and admission IDs, assistance, terminal status and explicit missing reasons.

| Landmark or label | Required evidence and rule |
|---|---|
| Planned opportunity | Exact manifest/scenario definition; distinguish a scheduled time, an event-dependent trigger and its declared fallback. |
| Exercised exposure | Actual `restart_begin`, `order_amendment`, or protected service disturbance plus its correlated exposure record. A scenario label or scheduled trigger alone is insufficient. Current restarts put the tracker record in `restart_begin.payload.exposure`; order changes have public `order_amendment` and protected `scenario_exposure` records. Retain actual trigger/fallback and delivery delay. |
| Admissibility | Explicit protected admissibility decision and predicate evidence under the frozen scenario rules. If absent, unknown. Reaching a timer, passing a unit test or later finishing the task does not establish admissibility. |
| Runtime return | `restart_ready` linked to `restart_begin`, with the new incarnation. This proves a worker returned, not that it reconciled the world. |
| First fresh relevant observation | First exact delivered `candidate_input.payload.message` with `type=step`, new/current incarnation, applicable current order, and a relevant sensor acquisition at or after exposure. Match to `observation` by sequence/incarnation and event links when available. A captured frame that was never delivered does not qualify. Stale or missing capture time stays unknown. Public order delivery and fresh visual delivery are separate landmarks when their acquisition clocks differ. |
| Behavioral detection | First candidate report that identifies the specific changed/ambiguous condition, or first demonstrably corrective action under the rules below. Link its exact delivered evidence and affected opportunity. Report may be incorrect; separately adjudicate correctness. Generic `observe`, generic help or an unrelated successful action does not establish relevant detection. |
| Correct reconciliation | Independent evidence agrees with the candidate's explicit resolution of the interrupted action, or a demonstrably compatible consequential continuation resolves the ambiguity before any contradictory/duplicate consequential request. Record both request-time and admission-time ordering. A fresh current-state inference can be correct without recovering historical cycle identity; label its basis accordingly. |
| Resumed useful work | First independently verified new progress for the current order after exposure and fresh delivery, causally linked to an admitted candidate action. Use the precise physical criteria below. Admission, planner completion, motion, `done` and a candidate `resolved=true` report are insufficient on their own. |
| Recovery | The affected task-validity condition is independently restored and useful work has resumed before the unchanged episode cap. Recovery time is the later of those two established times. Report from exposure and from behavioral detection separately; detection-relative time is unknown if detection is unknown. Recovery can be assisted; it is not synonymous with final task completion. |

For a restart, a fresh relevant packet must be acquired after the cut, delivered to the replacement worker and contain sufficient current public evidence for the resolution being assessed. A recent but occluded frame establishes delivery, not visibility of the affected part. Report first postexposure fresh delivery and first relevant visible delivery separately if needed. For order amendments, the exact delivered packet must contain the new order version; an image taken before the amendment can support unchanged geometry but cannot establish postamendment visual state. Do not infer that the model actually attended to every field it received.

## Corrective behavior and independently useful progress

Behavioral detection can be established without a verbal explanation when the trace proves a relevant correction: abandoning an obsolete allocation after a new order, requesting a new inspection specifically to resolve missing eligibility, or safely recovering an ambiguously held part and then reacquiring its identity. It needs an explicit opportunity/action relationship and evidence that the response fits the current state. Mere waiting, ordinary repetition, a schema rejection or a generic re-observe request does not satisfy this rule. Internal recognition, retrieval strategy, chain of thought and causal reason for the decision remain **unknown**, even when behavior is correct.

Use these physical checks for useful work:

| Progress type | Independent criterion |
|---|---|
| Processing | A uniquely identified accepted cycle reaches protected `cycle_complete`, retains valid seating/process provenance and satisfies an unmet current requirement or explicitly authorized rework. Reissuing `cycle` or seeing `cycle accepted` is not completion. |
| Inspection/reconciliation | A fresh completed inspection or independently verified current-state resolution removes the specific exposed uncertainty and is then used in an admitted, current-order-compatible continuation. Report information acquisition separately until that continuation exists. Never invent the missing historical cycle ID. |
| Physical transfer/routing | Protected geometry and relevant process/inspection records establish correct placement of the intended part in its current valid destination, with the frozen settling/acceptance criteria. `trajectory_dispatched` or feedback saying a trajectory ended is not physical success. |
| Setup/recovery | Protected state establishes the required compatible insert/resource/safe release and the candidate subsequently advances a current unmet requirement. A safe parked state alone is a recovery intermediate; if no useful continuation is verified, report it separately. |

An independently valid part produced entirely during the candidate's absence is autonomous process progress during the cut. It does not by itself establish **resumed candidate work**; require a postreturn compatible continuation that uses the changed state. A new order's future reuse opportunity is not proof that a procedure was retrieved or reused. Record actual repeated task context, observed use and mechanism missingness separately.

For an ambiguous command, classify `correct`, `incorrect`, `unresolved_at_end` or `unknown_evidence`. Candidate `candidate_action_resolution` records inside `candidate_reply.payload.events` explicitly have no grading authority. Compare the assertion against the protected outcome at its claimed time. Preserve a later correction without erasing an earlier wrong resolution. Loss of a 60-second receipt is unknown outcome, not proof of failure; repeating an idempotent request within the receipt window is different from repeating its physical work.

## Contradictions, duplication and staleness

Count gateway facts automatically where exact fields support them: stale order rejection, old incarnation rejection, duplicate suppression, repeated request ID, and repeated admitted cycle for the same part/recipe. Separate proposed/rejected actions from admitted actions and independently executed effects. A safely rejected obsolete request is a stale proposal, not performed wrong work. A suppressed duplicate request is not a duplicate physical cycle.

Adjudicate a **contradictory consequential action** only when its requested or executed effect conflicts with the current order, an independently known completed effect, or an unresolved opposing command on the same part/resource. Name the two event IDs and violated predicate. Acted-on obsolete allocation after a new order, cycling an already valid part without authorized rework, and declaring an uncertain transfer complete can qualify; a documented required retry, rework or fresh observation cannot be labeled avoidable duplication merely because it repeats an operation. Conflicting requests that the gateway rejects remain separate from physical damage/regression.

Distinguish unavailable fresh evidence from ignoring delivered fresh evidence. `action_requested.observation_sequence` must match the exact prior `candidate_input` sequence and incarnation. If no such packet exists, observation age/provenance is unknown. Retain acquisition-to-request/admission/dispatch ages; these do not prove which older context influenced the decision. Label avoidability, redundancy, target churn and hidden belief errors unknown unless a frozen predicate or blinded adjudication supplies the required comparison.

## Censoring, assistance and denominators

The recovery denominator is exercised **admissible** opportunities, with raw counts. Report planned-but-unreached, exercised-inadmissible, unknown-admissibility, missing-evidence and unfinished events separately. An unused trigger is neither successful recovery nor a zero-second recovery. A declared fallback is a distinct actual exposure mode; do not pool it with the intended cut phase without reporting the difference. An exposed admissible event with no recovery by cap is a recovery failure/right-censored latency; an unexposed event has no recovery latency.

Keep observed detection report, correctness of detection, useful resumption, restored validity and final completion separate. A corrective response may establish behavioral detection with recognition mechanism unknown. A missed explicit verbal report is not a missed detection if a demonstrably corrective action exists. False alarms require a specific unsupported disturbance claim and a known unaffected observation interval; otherwise their numerator/denominator remain unknown.

Any help request marks assisted behavior, even if the scripted answer is weak or arrives too late. Retain `help_requested`, `scripted_human_answer`, request/answer IDs, wait and response delivery. The common 15-second scripted advice neither reveals evaluator truth nor provides physical rescue. Actual human minutes remain unmeasured. Help, pause, model waits and restart do not reset the task clock or waive the cap.

Retain all failed and invalid attempts. Infrastructure exclusions and immutable continuation reviews affect the whole declared paired block for primary inference; remaining original block members can still be run and shown descriptively. Unknown validity stays visible. No automatic retries or per-policy replacement. Report numerator/denominator and paired case differences with both noise replicates clustered with their scenario family, as specified by the release analysis plan. Development traces cannot supply evaluation denominators.

## Relationship to implemented diagnostics and adjudication

[diagnostics.py](../Runtime/diagnostics.py) already supplies source hashes, `responsiveness.packet_deliveries`, `responsiveness.action_observation_ages`, `events.stale_order_rejections`, `old_incarnation_rejections`, `duplicate_suppression_events`, `repeated_request_id_count`, `repeated_cycle_admissions_same_part_recipe`, `context_io`, help counts, model usage/latencies and physical process intervals. Candidate context byte counts are reported serialization, not measured complete OS I/O. Model cache hits require measured counters; absent counters are not zero. Model wait/process-busy overlap is not proof of an idle interval's cause.

The diagnostics deliberately leave `successful_recovery_count`, `recognition_mechanism`, `independently_correct_resolution_count`, `avoidable_duplicate_work`, `avoidable_observation_requests` and `effective_physical_correction_latency` unknown until adequate evidence is supplied. This rubric defines the required separate operator annotations; it does not retroactively fill these fields. Current restart counters support nested `restart_begin.payload.exposure`, retain legacy top-level `cut`/`admissible` compatibility, and distinguish configured-milestone matches, actual cut modes and deadline fallbacks. They preserve nested exposure records and explicit missing-admissibility counts; a milestone match is not an admissibility decision. Order changes retain separate `scenario_exposure` records that require exact identity/version correlation with their public amendment. Absent admissibility evidence remains unknown, never false or zero; version-aware extraction and counterexample validation are still required for continuity labels beyond these recorded gateway facts.

Motion remains supporting evidence under the frozen diagnostics formulas: nominal 100 Hz positions, centered five-sample valid moving average, successive finite differences, no gap interpolation, squared Cartesian jerk on supported interior, and `T^5/L^2` normalization only for complete uninterrupted transports with path length at least 1 mm. Low motion means TCP speed below 0.001 m/s and all joint speeds below 0.01 rad/s for strictly over 0.25 simulation seconds. Physical/inference/reasoning labels require explicit supported interval annotations. A motion score never establishes recovery or correct work.

For interpretation-dependent labels, present traces with entrant/model/persistence identity masked where feasible. Preserve ordering, public inputs and independent physical evidence. The annotator records each rule, cited events, conclusion, confidence/missingness and competing interpretation. Disagreement or inadequate evidence yields unknown, with both annotations retained. Validate the extractor before scoring against synthetic cases for: capture without delivery; late old-incarnation output; suppressed duplicate versus executed duplicate; required rework; cut never reached; deadline fallback; process completion during absence; wrong candidate resolution; useful progress without explicit recognition; safe hold without resumed work; and snapshot-bounded correction time. Publish source/annotation hashes and unresolved coverage with the result.
