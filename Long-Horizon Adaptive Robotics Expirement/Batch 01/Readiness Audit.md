Read-only source review at 2026-09-23 03:33 UTC, during the A1-002 development pilot. No experiments, seeds, queue jobs or comparative results were produced by this audit. Later fixes must be checked against their own revisions; this is a point-in-time record. P1 means resolve before the scored release. P2 means resolve before making the corresponding interpretation. These are implementations of the existing Contract, Arena and Evaluation requirements, not additional approval gates.

The strict independent evaluator does check true containment, distinct identities, correlated process/inspection histories, extra tray occupancy, finite parking, empty fixture, contact, velocities, pending work, closed orders and stable terminal dwell. I found no concrete physical false-success bypass in those paths. This is a source audit, not proof over all executions.

## Release bookkeeping that still needs evidence

The known all-horizon baseline and A1/A2/A3 pilots remain prerequisites; this audit does not replace them. The readiness record must point to the resulting physical, sensor, timing, isolation and resource evidence, including 10-part late A release and the actual one-rework exposure. Development opportunity must be recorded per entrant, including shared-controller changes prompted by an entrant's failure; offer any extension symmetrically before freeze. A successful pilot does not justify setting every readiness boolean true.

The model adapter enforces the total token cap and disables prompt caching. Its present overflow behavior rejects the whole request rather than the deterministic low-priority truncation described in Shared Implementation Contract.md. Either implement that bounded context rule or freeze and clearly document fail-on-overflow behavior after checking extended/restart contexts. This is an explicit contract reconciliation, not a reason to change the common model after seeing scored outcomes.

The existing order service correctly counts five distinct completed B identities, records the 420-second fallback, closes only after its required order events, and keeps selected rework identity private. Later A work is an insert-reuse opportunity; anticipatory processing remains legitimate. Report actual setup counts instead of claiming two insert changes were forced. Do not add a hidden processing quota to force that claim.

The scoped first matrix does not establish every disturbance family in Arena.md. Physical actor disturbances, acknowledgement loss, sustained absence and controlled-delay diagnostics need their own explicit implemented exposures before conclusions about them. They must not be silently described as completed by an ordinary restart, and they do not require replacing the declared 264 runs.
