# Bounded physical calibration drivers

These files were prepared outside Runtime while the first five-pilot source revision was held unchanged. After official batch completion, the common changes in [Calibration Integration 002](../Calibration%20Integration%20002.md) were applied. **Physical calibration 001 has run; readiness remains false.** Its [official receipt](../../Evidence/queue-receipts/20260923T050529437896Z-06e48539.json) records succeeded/exit 0, while the [seven-probe summary](../../Evidence/calibration/physical-calibration-001/summary.json) retains five failed probes, one passed narrow effort comparison and successful static measurement collection. Source hashes were unchanged. The fresh [plan 002](../physical-calibration-plan-002.json) repeats the declared probes after repairs; no result from it is claimed here.

The driver runs no LLM and no scored architecture episode. It never changes an object pose, attaches an object, fabricates a placement result, or treats a trajectory receipt as physical success. Synthetic helper checks do not establish physical readiness.

`physical_calibration.py` must itself be the installed compute queue's recorded running child. It refuses an ordinary direct launch. The parent creates a fresh protected evidence directory and launches one bounded child per requested probe. The hidden child entry point independently checks the parent queue ownership. It does not submit jobs, poll queue status, register runs, generate held-out seeds, or amend readiness gates. Register each eventual calibration attempt before dispatch using the project's existing operator workflow.

Queue argv, after preregistration and release of any active source hold:

```text
<project venv Python> -X utf8 -B <absolute Calibration Tools/physical_calibration.py> --mode held-recovery --seed 0 --output <fresh protected operator evidence directory>
```

Use `--mode insert-exchange`, `held-recovery-parking1`, `adapters`, `effort-equivalence`, `raw-cameras`, or `static-sensors` for one probe; `all` runs insert exchange first, held recovery to each parking pad in separate fresh worlds, then the other four probes. The default is only `held-recovery` to parking2. Each directory must be new. A retry must have a new attempt and directory; earlier failures remain intact. `static-sensors` uses its declared fixed world list rather than the CLI seed.

| Mode | Fixed development scene | Simulation/owner wall cap | Hard child wall cap, including startup/cleanup | What is checked |
|---|---|---:|---:|---|

The sum of child caps for `all` is 1020 s. Parent source hashing, index writing, and up to 10 s of process reap after a timeout are additional bounded duties. Queue scheduling should provide sufficient headroom. A hard timeout preserves partial files and produces an explicit infrastructure-failure summary. Unexpected exceptions, cleanup failure, or source mutation also remain explicit. Completed physical predicate failures are results; the driver can exit normally while a probe's result says `failed`. Inspect the JSON summary, not merely the queue exit code.

The physics loop advances the actual Cell at its native 2 ms step while copied camera work and raw IPC/encoding execute asynchronously. It records actual wall/simulation timing. The paired comparison uses one common pre-step reference time for both worlds. Initial renderer setup and 250 settling ticks precede the measured clock. No simulation clock is fabricated to excuse slow rendering. A probe can satisfy its physical predicates and fail the separate actual-host timing check; both are reported.

## Interpretation and evidence

`insert-exchange` addresses the retained stacked-insert failure. It executes the shared setup service twice, requesting B and then A, without directly commanding hidden poses. The independent checks require exactly one insert at the fixture and the other fully contained at its own home; merely observing the requested insert or receiving a successful trajectory receipt cannot pass. Calibration 001 failed after returning A home because the driver omitted the supervisor's fresh-capture setup-resume call; B insertion was not attempted. The driver repair awaits a fresh probe. Four synthetic counterexamples check the predicate, including stacked inserts, protruding bounds and a held/moving insert.

`held-recovery` chooses the lexically first current image-derived raw workpiece. Protected geometry is used only to verify the intervention and final physical outcome. It requires exact workpiece/gripper contact, a measured closed width, and actual elevation before cancelling. This is an executor-authority interruption, **not a killed candidate process or persistence ablation**. The shared recovery primitive receives only its public destination. Final verification requires the selected identity's full collision bounds and center inside parking2, no other pad occupant, no hand contact, an open gripper, a settled robot and part, no outstanding work, and unchanged raw process state continuously for 0.5 s, checked each physics step. Parking2 is the current common center `(0.20, -0.09)` m. Its virtual full-containment region is checked; a trajectory completion receipt alone cannot pass this probe. Both calibration-001 routes failed before pickup because all initial markers were unknown, so no recovery was exercised. [Sensor Mark Calibration 002](../Sensor%20Mark%20Calibration%20002.md) records the image-only repair and retained-crop checks. A future successful probe would establish only its one capacity-one episode, not all approaches or payloads.

The adapter probe retains every command, receipt, clipping report and motion. Position/velocity/trajectory commands must exhibit positive joint-0 motion; the Cartesian command must exhibit positive Z motion. This prevents zero-motion acceptance from masquerading as tracking. The desired-effort hold additionally requires a correlated adapter-limit report. The equivalence probe uses the unchanged native gains, damping, hard control ranges and force ranges. It compares all-body qpos and qvel, actuator forces and controls after each physical step. It establishes only agreement of the two matched 500 Hz controllers over the declared small unloaded path; it does not establish pure torque-actuator equivalence or arbitrary 100 Hz effort-policy equivalence. Thresholds are retained in the result and must not be loosened after seeing a failure.

Calibration 001's adapter probe failed at joint position. The repaired normal completion preserves the bounded native target; the revised fixture measures local displacement at the unchanged 0.005 rad tolerance and separately reports absolute setpoint error. The original trace still fails that displacement check (0.006309 rad). The separate effort-equivalence probe passed 2,001 native steps over 4.002 simulation seconds, with identical all-body positions/velocities and actuator forces and maximum control difference 8.67e-19. See [Physical Calibration 001](../Physical%20Calibration%20001.md); neither result is a blanket arm-interface qualification.

The raw-camera fixture is copied into the existing CandidateSandbox, with only its private work directory and stdlib available. It requests each camera through normal IPC, decodes native filter-0 RGB PNG and float32 depth NPZ using stdlib, validates encoded hashes, dimensions/calibration, capture identity and timestamp, and reports decoded hashes. The operator compares those against immutable captured arrays. Expected bytes, protected truth and operator paths are never sent to the fixture. There is no silent resampling if the native payload exceeds the shared line cap. A payload-size rejection remains a failed round trip. This is a physical permission/data-fidelity check, not a claim that the selected language models can use images.

In calibration 001, overhead and oblique decoded and matched; wrist exceeded the unchanged line cap. The [lossless fallback repair](../../Engineering%20Investigation/raw-camera-payload-fix.md) compressed that retained wrist depth archive from 825,230 to 125,371 bytes with identical float32 bytes. It runs off the physics thread and binds distinct original/wire artifact hashes. This retained-frame check does not replace the pending fresh wrist sandbox round trip or timing measurement.

The static sensor mode retains each missing ID rather than assigning it zero pose error. It reports every observed signed axis error and Euclidean center error, per-sample visibility, never-visible IDs and maximum observed error. A `passed` status for this mode means all nine measurement records were collected with matching capture clocks; it does **not** mean perfect detection, calibrated confidence, or a satisfied perception-readiness gate. Comparison against the existing public `uncertainty_m=0.004` is explicitly diagnostic; its value and semantics are unchanged. Static initial scenes do not cover carried-tag occlusion, process-mark ambiguity, motion blur or a broad seed distribution.

All nine calibration-001 captures were collected. Maximum observed errors were 1.268 mm for three parts and 1.785 mm for six. B10 was missing from all ten-part captures; six of 33 observed positions exceeded 4 mm, with maximum 11.229 mm. [The retained-image diagnosis](../Ten-Part%20Sensor%20Position%20Diagnostic.md) attributes those biased centers to partial tags under robot occlusion. This remains a separate unresolved position/visibility issue; marker-core correction does not establish ten-part readiness.

Each attempted probe retains exact source hashes before/after, generated world XML, original RGB/depth files, action and sensor events, 100 Hz full-state trajectory records, 10 Hz protected snapshots, final protected state, timing and failure traceback. Held-cut/final checks have dedicated records; the equivalence probe additionally retains every 500 Hz paired state. Raw IPC and sandbox handshakes/decoded replies remain protected artifacts. The top-level source bundle preserves Python, Markdown and XML sources; Panda mesh files are identified by exact hashes but not duplicated. `evidence-index.json` hashes the final evidence files. These files contain evaluator data and must remain outside candidate-mounted directories. Only `fixture-work` is mounted into the calibration fixture.

## Restart admissibility: implemented records, measured qualification open

The phase selector remains an exposure opportunity selector, not proof that the cut is physically recoverable. [restart_state.py](../../Runtime/restart_state.py) and the supervisor now retain the protected physical snapshot, exact cut/source hashes, required pass/fail/unknown predicates and optional prior calibration before revoking authority. Hidden identities, truth and admissibility decisions do not enter candidate input. The implemented checks cover common validity, empty/released versus held state, supported grip/route geometry and device/resource state. Missing measured envelopes remain unknown; no accepted prior grip/route calibration is supplied.

The classifier records the selected exposure; it does not choose an easier cut, redraw seeds or assign paired-block exclusion. Candidate-induced loss of free buffers is not automatically infrastructure invalidity. [Continuity Analysis Rules](../Continuity%20Analysis%20Rules.md) preserve unknown and unexercised opportunities. [Restart Calibration Qualification Plan](../Restart%20Calibration%20Qualification%20Plan.md) states the fixed-hash qualification limit and prospective transfer proposal; it is not accepted calibration evidence. A completed probe at one seed supports only its measured envelope.
