# C0-004 output-cap diagnosis and common IPC fix

Development evidence only. No scored release or robot-performance success is established by this repair.

`Evidence/raw/B01-dev-C0-004/events.jsonl` event 17525 records the exact sandbox failure, `Candidate exceeded the combined output cap`, at simulation time 769.6539999956238 s. Event 17526 classifies the resulting IPC termination as `candidate_transport_failure`; event 17529 repeats the same diagnostic. Here "transport" means the candidate communication channel. The terminal file reports execution failed, validity unknown, and host timing passed. This is a 10-part baseline persistent nominal episode with a 900 s cap. Its independent outcome counted nine accepted parts, which does not satisfy the whole task.

The executed wrapper and sandbox source hashes in the retained manifest matched those files before this repair. Their shared stdout/stderr cap is 32 MiB. The reader checks that cumulative actual wire-byte count after each read; the terminal diagnostic does not retain the exact count. The evidence therefore proves a cap crossing, not an exact final byte count. The final three retained replies (17515, 17518, 17522) each return `wait` and include a full checkpoint write, alongside uncorrelated feedback. This diagnosis uses bounded tail reads, not whole-run aggregation. Other physical/progress failures remain separate questions.

The common repair changes only `Runtime/candidate_worker.py` and `Runtime/sandbox.py`. The wrapper losslessly compresses large `context_read` and `context_write` text into a reserved zlib/base64 IPC carrier. The receiver bounds decompression, verifies the original UTF-8 byte count and SHA-256, and restores the original event before evidence storage or downstream consumers. The candidate code, durable checkpoint bytes, checkpoint frequency, observation timestamps, and stored event schema are unchanged. The 32 MiB quota still counts actual pipe bytes. The original 1 MiB full decoded reply cap is enforced before compression and again after restoration; compression cannot enlarge the allowed reply. Uncompressed legacy replies remain accepted. Invalid carriers fail closed.

Fifteen focused synthetic checks in `Runtime/test_context_transport.py` passed. They cover exact Unicode and field recovery, both context event types, legacy compatibility, malformed/truncated/trailing streams, metadata/hash checks, bounded expansion, combined decoded budget, original reply limit, actual wire-byte accounting, unchanged quota, and wrapper usage fields. These tests do not launch a sandbox or run physics.

The bounded three-reply sample in `C0-004-output-cap-sample.json` re-encodes the retained original worker messages after removing the supervisor-added input reference. Their reconstructed original wire lengths are 8,903 / 8,912 / 8,921 bytes; compressed lengths are 3,766 / 3,766 / 3,765 bytes, a 57.7–57.8% reduction with exact message equality after restoration. This sample is not a total-run compression measurement or a guarantee that a later episode stays within the quota. The JSON records event payload hashes and the revised codec source hashes.

Actual sandbox/physical validation remains for the parent's queued calibration and later development episodes. Historical run evidence is unchanged; the failed episode is not relabeled successful by this prospective repair.
