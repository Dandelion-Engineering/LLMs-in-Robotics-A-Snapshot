# Integrated closeout failure and candidate repair

Release001 failed its first real pilot closeout even though the model completed, docked and retired normally. The outer workspace unmounted, but the journal service stayed alive through both normal retirement waits. The inherited campaign005 service explicitly handled mount clones retained in native namespaces. Session38's race repair made its retirement command observation-only and relied on unmount to end the service. The live failure exposed the missing integrated shutdown path.

The precise owner of the pilot's retained namespace was not established. Its symptom is consistent with that documented mechanism. A new isolated private-namespace fixture holds a clone alive across outer unmount and exercises the repaired path directly; it does not claim to identify an earlier namespace after it retired.

Abnormal SIGTERM cleanup ended native001 with service exit 1. It **did write** final journal record 7990, contrary to the initial terse result narrative. The immutable result is accompanied by a correction note, not replaced. Independent readback authenticated 4,213 mutations, 3,505 reads and 4,185 content versions, with final state `e0c8dbd504cb149c7adf2a196508c6db8963f251e1cfb7321c81dd154da60f51`. No accepted native-exit receipt or normal session checkpoint exists, so this remains a failed, non-resumable engineering attempt. The complete native001 inventory was preserved unchanged.

The three-file release002 repair adds a protected cooperative request after outer unmount. The service checks owner identity, mount absence, no open handles, readiness and journal health. It holds the journal mutex while recording the request and asking libfuse to exit, then wakes the blocked native read with a harmless SIGUSR1 handler. The FUSE context is captured inside initialization and invalidated inside destruction under the same mutex. Actual destruction remains responsible for the final record. Duplicate destruction returns without appending; post-finalization controls cannot write. Nonzero native returns, external termination and poisoned journals remain failures. There is no timeout extension, source change within an attempt, or scientific parameter change.

Retirement001, queue `20261009T235548264530Z-43e40a77`, succeeded with integer exit 0. Five ordinary unmounts passed. With the clone still alive, actual service retirement and exact journal/content readback completed in 0.344 seconds; the native return was 0 and there was exactly one final record. External SIGTERM and poisoned journals were refused as normal closure. Workspace002 then independently repeated the full workspace matrix, including a forced post-finalization retirement/checkpoint race, ownership failures and isolation.

These are engineering findings, not a commissioning certificate. The [live status](STATUS.md) records full release002 qualification, independent audit and the conditional official-launch boundary.
