# B01-A3-r1 — Grounded Objective Composer

**Status: proposed design.** This is Batch 01's task-space objective candidate. There is no implemented optimizer, running model, frozen executable or measured result attached to this revision. Common resources and gates are in the [Shared Implementation Contract](../../Batch%2001/Shared%20Implementation%20Contract.md). The experiment's [Contract](../../Long-Horizon%20Adaptive%20Robotics%20Experiment%20Design/Contract.md), [Evaluation](../../Long-Horizon%20Adaptive%20Robotics%20Experiment%20Design/Evaluation.md) and [Evidence](../../Long-Horizon%20Adaptive%20Robotics%20Experiment%20Design/Evidence%20and%20Investigation.md) retain their authority.

## Contribution and complete loop

A conventional durable job scheduler chooses the next eligible operation. The LLM converts that operation and its sensed scene into a bounded objective/constraint specification for a numerical receding-horizon motion planner. The numerical planner repeatedly updates executable movement using current public state; the shared controller tracks it. The LLM neither schedules the entire job nor supplies joint torques.

The loop is: reconcile order and progress → choose eligible operation → build versioned geometric belief → retrieve relevant objective/correction → compose and validate objective → optimize bounded movement → execute and reobserve → independently check the operation's visible outcome → update job state. The model contributes how the selected manipulation should proceed through the current geometry. Its value must therefore be assessed relative to the substantial scheduler, sensing and numerical-control machinery surrounding it.

The planned common text model is **Qwen3-4B-GGUF, official Q4_K_M, with thinking disabled**, subject to local resource, artifact and terms verification. It is not installed or frozen here. Calls have a 16,384-token total context ceiling, including at most 1,024 output tokens. Exact weights, quantization, runtime, prompts and generation settings must be recorded before freezing. No remote or paid fallback is assumed. An invalid output is rejected; the numerical planner does not silently invent the missing model contribution and attribute that action to the LLM.

## Scheduler, observations and belief

The deterministic scheduler tracks part identity, order version, fixture compatibility, available buffers, public cycle state, inspection outcomes and unresolved operations. It selects from a declared operation vocabulary: observe, change insert, load, unload, inspect, route, wait and request help. Eligibility and bounded recovery rules are authored code, with effort recorded. They cannot query the private evaluator. This scheduler is competent and durable, like the conventional comparator, but is not assumed identical until its actual implementation is documented.

Inputs are the common image-derived visible tag poses with covariance and acquisition time, sensed depth obstacles, calibration, joint/gripper feedback, public process I/O, current orders and candidate command feedback. A scene adapter expresses object-relative frames, observed free/occupied regions and uncertain geometry as typed text for the model. The text model does not read raw RGB images in this revision. Invisible objects are unknown or last observed with age, never supplied from simulator inventory. An observed empty region is limited to the sensor coverage that supports it.

The geometric belief combines current observations with the candidate's retained records. Every estimate identifies its source, uncertainty and version; old pose estimates do not become fresh because they were reloaded. Object, order, operation and calibration versions bind an objective to its intended scene. Public fixture geometry can be known, but occupancy and current part location must be sensed. Exact simulator contact pairs and hidden inspection results remain inaccessible.

## Model output and numerical execution

The model emits a typed objective record, not executable cost code. Proposed fields include operation/part/order bindings; target region; allowed approach frame and orientation interval; clearance preference; approved keep-out regions; bounded velocity preference; completion-observation request; and validity/freshness conditions. A fixed expression vocabulary can compose distance-to-region, orientation alignment, clearance and movement-effort terms with bounded weights. The model cannot invent functions, disable protected constraints, access files, or change machine eligibility.

Validation checks referents, coordinate frames, dimensions/units, numeric bounds, observation provenance and consistency with the chosen operation. Required collision limits, interlocks and allowed workspace remain hard constraints outside model authority. Task-specific constraints are distinguished from soft preferences; an attractive target never overrides a forbidden region. Conflict or infeasibility returns an explicit diagnostic, rather than relaxing a hard constraint until something moves.

The numerical planner uses the current arm state, public kinematics/geometry and sensed obstacles to propose a short joint-space trajectory satisfying the objective. It checks the whole arm and declared payload envelope, not just end-effector clearance. Planning horizon, discretization, solver budget and update rate require common calibration and freezing; this proposal does not claim a real-time rate has been achieved. Failure to find a feasible solution is logged as such, not proof that none exists.

Gripper transitions and contact-sensitive loading use declared common primitives and eligibility guards. The optimizer does not infer successful grasp, seating or inspection from a low cost value. Candidate-visible verification follows actual feedback and fresh sensing; the private evaluator independently grades physical success. No contact-dynamics learning or universal manipulation competence is assumed.

The resulting trajectory enters the same executor and low-level actuator/safety layer as other candidates. Commands carry unique request/incarnation IDs, order version, parent objective and decision IDs, deadlines and resource ownership. Shared primitive/path services remain available to all entrants. Any new numerical planner introduced for this candidate must be versioned and offered as a documented common optional service, with usage and resource costs recorded. Full-system comparisons still include differences in how candidates use that service.

## Timing, modifications and uncertainty

The numerical loop can reevaluate a still-valid cached objective against newly acquired geometry while an LLM call is pending. That is the candidate's explicit source of responsive motion. It does not pause physics, restore old observations or assume newly generated geometry is evidence. Accepted commands expire within two seconds before reauthorization. Renewal requires current objective validity, adequate observation freshness, a live resource lease and a feasible numerical solution.

A modest observed object displacement can change numeric targets without another language call if it remains inside the objective's declared binding and validity region. A changed order, unknown identity, incompatible task phase, failed manipulation or major scene conflict invalidates the objective and triggers reconciliation or recomposition. The scheduler stops assigning dependent operations until their evidence requirements hold. Replacement objectives become active only at an acknowledged cancel/supersede boundary; target changes and their causes are logged.

Covariance, occlusion and observation age determine whether to observe again, use a conservative geometric margin, or hold. Thresholds are calibration choices to freeze, not model confidence estimates. An unknown target cannot be filled with a convenient prior pose. Repeated infeasibility invokes bounded alternative proposals or explicit help; it cannot produce an endless sequence of unproductive target changes. Concurrent machine processing may continue under public station semantics while the arm holds.

## Filesystem continuity and restart

The persistent episode store contains a durable scheduler ledger, unresolved intent/receipt records, versioned geometric belief snapshots, objective specifications and provenance, and verified within-episode corrections. Atomic checkpoint replacement references a checksummed journal prefix. Intent is committed before dispatch; verified outcome is separately committed after candidate-visible checking. Numerical solver state and the most recent trajectory are expendable warm starts, never proof of progress.

Restart validates the stored prefix, marks torn or unmatched entries unresolved, obtains a new incarnation and acquires current orders, device I/O and fresh observations. It consults the public receipt window where available. All saved objective-to-scene bindings are revalidated. A trajectory from the previous incarnation is never simply replayed; the planner begins from the current sensed arm/payload state after any uncertain in-flight outcome is reconciled.

An objective can survive as a reusable specification without its cached target coordinates remaining valid. If public state and observations cannot establish where a released part went or whether a process became eligible, the scheduler keeps that operation unresolved and observes or escalates. The 60-second receipt window is not a private long-term job history. Restarts do not undo machine timers, reset the world or permit a second process cycle just because an old ledger lacks its terminal entry.

## Concrete designed episode

The scheduler selects routing an inspected A part to the current destination. The LLM specifies the tray's sensed target region, an approach orientation and clearance around the occupied parking slot. The optimizer repeatedly replans against current observations and sends bounded trajectories. A process crash follows physical release but precedes the durable placement check. During absence an external actor moves the unheld part and an order amendment changes a later B destination. This is a schematic example, not an observed run.

On restart the A placement remains unresolved. Fresh detections locate the part outside its intended tray, so a previous small objective value cannot mark routing complete. The scheduler verifies identity and inspection provenance from surviving records and public evidence, then requests an eligible corrective operation. The old target cache is invalidated; the model composes an objective against current geometry and the optimizer plans from the actual arm state. The amended B destination changes later bindings without erasing A's verified processing history. If A's identity or eligibility cannot be established, further observation/help replaces speculative handling.

## Controls, evidence and limits

Persistence ablation uses the same scheduler, model, optimizer, prompts and controllers while private ledger, belief and objective history becomes ephemeral and disappears on restart. Current orders, public device state and bounded receipts remain. The scheduler's normal initialization supports empty state and explicit unknowns; any compensation that changes behavior beyond available state must be declared as an adapter. Optional summary-only memory cannot conceal geometric caches or a private ledger in another channel. Model recomposition, renewed observation and reconstruction cost all count.

Evidence includes actual model context and typed outputs, scene/objective versions, solver inputs/status and consumed time, feasible/infeasible returns, paths and supersessions, observation age, command lifecycle, candidate verification and independent outcomes. Log missing optimizer internals as unknown. Cost reduction is not success; smoothness must be reported alongside duration, collisions and useful work. A model-free fixed-objective diagnostic using the same scheduler/controller can test the objective composer's contribution without pretending it is a fourth main candidate. Persistence claims require matched within-candidate controls.

Missing implementation includes the arena and calibrated baseline, visible sensing, scheduler/ledger, scene adapter, objective language/validator, numerical planner, manipulation primitives, model adapter, protected execution and evidence/timing infrastructure. There are no measured performance, licensing-completeness or real-time guarantees.

[VoxPoser](https://voxposer.github.io/) (literature ID `arxiv:2307.05973`) motivates the conceptual separation between language-derived spatial objectives and numerical motion generation. This design uses bounded typed specifications instead of unrestricted generated cost code. It does not copy paper code, reproduce its experiments or inherit the released demo's privileged simulator masks. The source establishes no result for this local model, scheduler or workcell.
