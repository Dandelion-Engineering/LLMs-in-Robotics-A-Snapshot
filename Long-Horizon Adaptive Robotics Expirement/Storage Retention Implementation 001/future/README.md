## Storage and scientific boundary

`recorder.py` uses a versioned SQLite container with exact typed binary objects, zlib compression, SHA-256 content references, and ordered telemetry spans. JSON floats are stored as IEEE754 float64, including signed zero. Integers remain integers; null, booleans, exact Unicode/model text, nested objects and arbitrary additional fields are preserved. There is no downsampling or lossy numeric conversion. The writer stores every supplied motion row; chunks retain every diagnostic field, original time, gap, flag, and unknown field. An observation's `telemetry_history.samples` becomes exact ordered row-ID ranges. A changed sample value receives another identity; gaps, repeated occurrences and stale order are never inferred or interpolated.

Large repeated dictionaries, arrays, strings, public packets, model requests/responses and checkpoint text are content addressed. Candidate-input objects can reference the same stored public packet objects. Event envelopes retain original event IDs, parent IDs, source, acquisition/delivery/model/command clocks and payload digests. The format promises exact reconstructed JSON objects and file/model content, **not literal historical JSONL byte reproduction**. Historical migration is a separate prototype.

Version 3 retains version 2's shared canonical telemetry across structured packets and JSON text whose keys were sorted. Each occurrence records its original field order. A bounded JSON-text recipe is used only when a declared formatting operation reproduces the complete original string exactly; unmatched lexical forms remain opaque strings. Fewer tiny nodes are eagerly interned, and related objects can use bounded standalone compression dictionaries. These changes reduce physical duplication and SQLite overhead without discarding event fields, numeric bits, model text or checkpoint bytes.

Version 3 finalizes the exact SQLite bytes into `evidence.sqlite.gz`, independently checks full decompression against the original byte count/SHA-256, and retains a manifest binding both representations. Only this newly created writer's working SQLite file is discarded after successful verification. The hard 512 MB live-container cap limits working-plus-finalized disk overlap to 1.025 GB for one queued writer, within the existing 2 GB temporary allowance. Readers restore into memory with at most 512 MB input buffer plus a 512 MB SQLite copy, a separate 64 MB encoded-object cache, and no temporary disk file. The limit applies per open reader; caller-owned decoded event collections require their own memory budget. `FORMAT.md` specifies the version and failure boundaries.

The database is protected operator evidence. Never mount it inside a candidate sandbox. `GatewayAdapter` records a supplied public message and sends that exact original object. It never constructs candidate input from protected evidence. The reader exposes separate events, motion, documents and image-availability APIs to analysis, diagnostic, continuity and selected-package consumers. Close writes a compact `container-manifest.json` with bytes/SHA-256 for the entire database; opening the reader checks it before decoding any table, including envelope/availability metadata. Available images and numerical chunks are also individually hash-verified. A policy-retired frame returns `unavailable_by_policy` and a reason; corruption of an available image is an error. `require_images()` makes fixed selected-viewer dependencies hard failures; the package writer preserves unavailable slots without replacement.

## Live images and permanent policy

`runtime_adapter.py` supplies a concrete future `Evidence` API (`emit`, `motion.write`, `document`, `trigger`, `close`) plus `LiveSensorBridge`. A new runtime can import it without changing its existing event/numerical call sites. Disable per-capture raw artifact paths at the future `SensorWorker.request(rgb_path=None, depth_path=None)` call, then pass its immutable completed result to the bridge. The bridge returns the exact same result/arrays for live perception and delivery; its separate persistence path encodes a paired RGB/depth record into a bounded memory ring. No full 10 Hz image directory is first written and later cleaned up.

The provisionally qualified campaign policy is 30-second sparse pairs, twelve **predeclared** representative spans of up to 600 seconds each at 2 Hz, and up to 128 **outcome-selected** five-second anomaly windows (2 seconds before, 3 after, at the live 10 Hz acquisition rate). These are explicit span limits, not a promise to retain all imagery of every 900–1200-second run. Budget projections count category overlaps twice rather than claiming unmeasured deduplication savings. The ring is bounded by 24 MB, 64 pairs and 2 seconds; inability to cover the full requested pre-window is recorded. Full run/packet/numerical/model evidence remains mandatory even when image quota is exhausted.

Representative quota is a required allocation. The default 22 MB is only a small standalone nonrepresentative pilot limit; do **not** use it to provision a 600-second representative span. Allocate the measured maximum paired-image bytes times the declared number of representative pairs, plus its sparse/trigger allowance. `require_complete_representative=True` makes quota exhaustion a recording failure rather than quietly truncating promised representative footage. Other unselected imagery can be explicitly unavailable by policy. Complete intended viewer selections must pass `require_images()` during qualification.

Use `CampaignReservations` to reserve all per-run core/image/window maxima before admission. The SQLite ledger rejects duplicate run IDs, aggregate budget overruns and trigger allocations above 128. Pass each returned immutable allocation to `FutureEvidence`. Allocations cannot be silently reclaimed or revised to admit more work. This conservative reservation scheme may reject a campaign whose mean use would fit; that is intentional. A candidate-specific future campaign must qualify its own maxima and representative selection.

## Qualification and admission

Run `qualify.py` through the shared compute queue with a fresh explicit `--generation` name (for example, `--generation qualification-008`). Existing generation directories are deliberately not overwritten. It creates ignored `pilots/` evidence once and writes compact `qualification.json`; preserve the previous report/receipt/source snapshot before starting a new generation. The cases replay ten bounded real r4 source windows across baseline/A1/A2/A3, C01/C14/C24 and the large C20 failure stream. Diagnostics compares original versus decoded windows. Continuity requires complete event chains beginning at event one: two complete baseline/C14-A3 chains are compared without weakening that requirement. Synthetic edge tests cover delayed/missing/repeated/stale packets, restart/checkpoint/model context, full-precision numeric gaps, image ring/trigger/quota behavior, corruption, and rejection/stop behavior. A full 1,200-second synthetic recorder workload exercises 120,000 numerical samples, 12,001 live pair metadata records, 240 model-call fixtures, 120 checkpoints, a gap and restart; its artificially compressible bytes are excluded from projections. Separate fixtures exercise the frozen protected evaluator and the immutable-array bridge.

`native_supervisor.py` is a separately versioned, concrete component runner. It wires the frozen physical `Cell`, public telemetry, real asynchronous sensor, raw response encoder, independent evaluator, and frozen `TimingMonitor` into the future backend. Its queued qualification compares two ten-second real workcell passes, with and without recording, including two fixed small joint commands: exact admission/feedback/final physics/scoring, unchanged live sensor object/array/metadata, no full-stream image files, sparse image availability, and actual host timing against the frozen 0.95–1.05 RTF / maximum lag under 0.1 seconds rule. Timing failure fails qualification without relaxing the tolerances. `NativeRawGateway` retains exact requested live image encodings as deduplicated core decision evidence while leaving the live response encoding unchanged. One matched raw request checks exact wire bytes and metadata after the timed fixture; it does not qualify sustained raw-request throughput. The runner has no model, candidate sandbox, Architecture Map writer or scored-release entry point. This is engineering qualification, not a new robot experiment or scored attempt.

Measured finalized container bytes include compressed database/index/page overhead and the complete manifest and are projected at the **maximum** observed core bytes per task-second over 156,600 task-seconds and 264 runs. Actual RGB/depth sizes from thirty fixed sample pairs supply frame-category projection. Every image input, including the repeated-pair policy fixture, is selected exclusively from the authenticated `r4-policy-001-retained.jsonl.gz` manifest (SHA-256 `55569a0375eacc9c71dc39e9e3b006392c657e7619b21f3f196c5a91f67bc09d`). Explicit paths and source hashes are frozen in `image-inputs.json`; source bytes and both paired manifest memberships are checked. The 0.1/0.5/0.9 path quantiles within retained pairs are bounded engineering size samples, not a scientific representative sample. They remain reproducible after frame retirement. The projection includes 1 GB compact provenance, 4 GB packages, 2 GB development, 25% uncertainty, 2 GB temporary/build space, and per-run container overhead. Image allowance is the larger of 6 GB or the measured category projection plus availability metadata. The 30 GB target concerns permanent footprint; the 40 GB gate includes temporary/uncertainty headroom.

After the queue reports `state=succeeded` and `exit_status=0`, save its receipt and call `bind_qualification()` to create `qualification-binding.json`. Binding requires the qualification schema and passing tests, the exact qualifier script/working directory/generation arguments, and a report timestamp within the successful queue job's execution interval. An unrelated successful optimization/census receipt is refused. The admission CLI repeats these checks and verifies the report, receipt and current implementation hashes against the seal before using measured projections. Changed code invalidates qualification. It refuses campaigns above 40 GB, an evidence footprint above 150 GB after adding reservations, or a projected free-space remainder below 100 GB. Every large batch still requires its existing independent scientific/release authorization.

Admission measures current free bytes on the actual output volume itself. Its capacity input names `output_directory`, an `evidence_census` binding (`path`, `sha256`), and optional `outstanding_reserved_bytes`. Use `write_capacity_census(EXP, output)` through the shared queue while writers are stopped. It counts the **whole canonical experiment directory**, including Evidence, every viewer/package, pilots, prototypes, code and model/runtime trees, with no subtree exclusions. This is conservative: model hardlink pathname sizes and code also consume the gate's 150 GB allowance, although the adopted scientific evidence ceiling does not inherently require that overcount. A later separately qualified physical-identity/model-exclusion census can refine this; the current gate cannot hide evidence in an excluded runtime directory. Missing/wrong roots, unrecognized scope, reparse/junction subtrees, outputs outside counted scope, changed hashes and censuses older than one hour are refused. Caller-supplied `free_bytes` is ignored. Negative, nonfinite, boolean and noninteger byte/reservation values are rejected.

Do not catch `RecordingFailure` and continue a scientific run. The supervisor must stop it, preserve the bounded `RECORDING_FAILED.json`, and classify the result as an evidence-recording failure. The reader refuses incomplete/failed recordings as complete scientific evidence. Motion buffers are bounded at 1,000 rows; an abrupt process failure can leave the current chunk uncommitted, so unclosed recordings are invalid. Normal event commits are atomic with their referenced objects. Filesystem/I/O exceptions must use the same explicit supervisor failure endpoint.

## Remaining integration gate

The native component runner, adapter and tests are implemented; frozen r4 is untouched. Offline replay establishes exact objects and stored clocks; the real fixed-action workcell fixture tests one bounded asynchronous load. A **new** candidate runtime must connect its orchestration to these service hooks, preserve failure handling, freeze the resulting release, and run representative whole-task/restart/inference timing qualification before scored use. Neither the fixed-action fixture nor exact replay establishes that wider property. Current admission therefore keeps `runtime_timing_qualified=false` and `frozen_release_bound=false`. The component integration is runnable while admission prevents it from being mistaken for a fully qualified scientific release. The measured projection is for r4-shaped public/numerical/model traffic; an image-heavy future Robot-Codex workload can have a different core rate because exact raw responses are decision evidence. Such a release must supply new workload-specific pilots, not reuse this projection as a hard bound for unseen traffic.

Do not claim historical pixel recreation, general timing equivalence, a completed full-campaign measurement, or scientific performance improvement from these pilots. The storage implementation can support the requested Robot-Codex integration work; it does not itself authorize that work or a batch.

## Visible implementation corrections

The first queued qualification (`20260927T005611166563Z-f146c346`) failed on a native public-packet tuple. Frozen JSON serialization converts Python tuples to JSON arrays; the initial binary encoder accepted only lists. The corrected codec uses that same JSON-array semantics and has a regression assertion. `failed-001-queue-receipt.json`, `failed-001.log`, and the original ignored partial pilots preserve this failure. Native-supervisor exceptions now mark a failed recording explicitly. Fresh qualification generations use separate directories; no failed output is overwritten or treated as qualification evidence.

Generation 002 (`20260927T011100905382Z-3d64b4ac`) was canceled when the final retained partition became available, so every subsequent image sample could be restricted to its authenticated retained members. Its official canceled receipt and partial log are preserved as `canceled-002-queue-receipt.json` and `canceled-002.log`. It is not used as qualification evidence.

Generation 003 (`20260927T015324849475Z-cb88a09f`) completed successfully and passed its semantic, diagnostic, continuity and bounded native timing checks, but failed the storage budget: 79.57 GB permanent / 101.46 GB including headroom. The full report, official receipt, log, Python source snapshot and bounded table profile are preserved in `history/qualification-003/`. Its successful execution is not a sustainable-budget qualification. The first version-2 development comparison is separately preserved in `history/optimization-004/` and also failed the target; it led to the bounded dictionary and SQLite-layout corrections. Neither result is overwritten or promoted to scientific admission.

The successful `history/optimization-005/` development comparison measured both exact version-2 SQLite and losslessly finalized gzip bytes on the two largest version-1 pilot windows. Its best 8,192-byte interning threshold reduced the high-volume window to 3.35 MB SQLite / 2.47 MB finalized bytes, motivating version 3's measured finalization design. This development comparison is not full qualification.
