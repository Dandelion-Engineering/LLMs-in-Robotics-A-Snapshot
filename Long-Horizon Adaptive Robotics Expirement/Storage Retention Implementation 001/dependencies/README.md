# Current image dependencies and diagnostic windows

These tools create additive retirement inputs and validation records. They never delete, move, rewrite, or copy original evidence. Heavy scans and production-reader checks must run through the shared compute queue, with official `succeeded` / exit `0` status recorded before consuming outputs.

`extract_dependencies.py --output <fresh-directory>` authenticates the current Investigation007 twelve trace manifests and Explorer projections, includes the saved source-bound validation004 first trace, searches tracked source text for literal r4 image references, then streams r4 event headers. The extractor reads no camera pixel bodies. It hashes the original event bytes during that one pass, checks the payload hashes of diagnostic anchors, extracts original capture identities and image hashes, and separately reads numerical motion for the ten largest recorded contact peaks. It recomputes the unchanged original selected-observation rule for all twelve fixed traces.

The output `retained-inputs.jsonl.gz` is a deterministic compressed JSONL dependency set. Every row contains repository-relative `path`, `reasons`, `dependencies`, `source_identities`, and, when an original reference supplies it, `expected_sha256`. The retirement pipeline must measure and hash each retained file and compare its current hash with `expected_sha256`. This dependency file is not itself the final size/hash-bound retention manifest. `windows.json` records every chosen interval and actual saved observation count. `scan.json` records all inspected runs and anchor counts. `decisions.json` binds input/code hashes, actual consumers, selected trace identities, discordant pairs, and inspected calibration/rebuild rules.

The window rule preserves **all originally saved RGB/depth captures within each bounded interval**:

- Valid task failures and infrastructure-invalid cases: twenty seconds before the recorded physical endpoint, plus up to two seconds after it if captures exist. These remain separate dispositions.
- The administratively interrupted run: the final twenty seconds of available capture history and first five seconds. Its physical ending and outcome remain unknown.
- Incorrect completion claims: first and last occurrence of each distinct recorded reason, with five seconds before and after. Routine unsettled-arm claims in eventual successes remain distinct from the C20 replicate2 baseline's repeated incorrect claims. The latter's entire 1,861-claim history remains in untouched events; it does not create 1,861 visual windows.
- Actual runtime restarts: five seconds before and fifteen seconds after every recorded restart. These retain physical context for continuity and ambiguous in-flight actions without asserting successful recovery.
- Explicit physical failure/ambiguity or runtime anomaly event classes: first and last occurrence per recorded reason/type, with five seconds before and after. Watchdog, model errors, terminal errors, stale/invalidated model output and missing candidate usage tails remain labeled as recorded technical evidence.
- Protected scenario interventions: first and last, five seconds before and ten after, without a new admissibility judgment.
- The ten largest all-run recorded contact peaks: five seconds before and after the corresponding sampled numerical-motion peak. A 100 Hz sample can miss a native-rate peak; high contact is not automatically an unintended collision.
- Both sides of the two eligible baseline/A3 discordant pairs, C20 replicate1 and C20 replicate2: ten-second windows centered on each recorded episode quartile, plus the final thirty seconds. Identical rules apply to both members.

The current-viewer/fixed-selection images were predeclared. These additional diagnostic windows are selected after outcomes and **are not a representative statistical sample**. Completeness means every saved observation in the selected intervals; sensor gaps remain gaps and no missing pixels are synthesized. Unmapped or calibration artifacts under the affected frame directories are retained conservatively. Non-image evidence, external qualification sources, and images outside the affected r4 trees remain outside retirement.

The original 005 reader samples observations before calling `artifact_ref`. Therefore an exact selected-trace rebuild needs the 2 Hz observations plus parent-linked and final observations; it does **not** read every 10 Hz image. It still reads and authenticates complete original event/motion/result/manifest/terminal sources. Aggregate analysis uses compact results/manifests; diagnostics uses events/motion/result; continuity uses event/state/restart/calibration evidence. These dependency findings do not turn a prior validation into a post-retention validation and do not claim that discarded images can be recreated.

`validate_policy.py --required <retained-inputs-or-final-manifest.jsonl.gz> --output <fresh-directory> --phase staged --actual-reader all` applies a process-local availability guard: every affected r4 PNG/NPZ outside the proposed retained manifest behaves as absent. It first tests the guard itself, checks every current trace and source-bound validation frame reference, authenticates all 264 derivative dispositions and unchanged analysis through the original production readers, then runs the unchanged selected reader and `trace_package.verify_trace` on all twelve original packages. This compares full metadata, every retained event payload and motion sample exactly against the historical package. Finally it runs the unchanged Explorer validator under the same policy. It writes only a compact `validation.json`; no replacement package is built. `--phase post` repeats the check after retirement. `--actual-reader first` is available for a bounded diagnostic probe but is explicitly recorded and does not represent all-twelve reader validation.

The guard's boundary unit test checks retained image reads, denied image opens/stats, unaffected event streams, and restoration of normal filesystem access. It does not replace the production-reader gate. No current test or frozen source is weakened.

Pass `--windows <extraction-directory/windows.json>` to the policy validator to also run `validate_windows.py`. This independently reconciles the required/final retention manifest with every declared interval: exact saved observation count, matching run, one RGB and one depth artifact per observation, capture timestamps inside the interval, and exact first/last saved capture bounds. Its authenticated result is included in the policy validation record.
