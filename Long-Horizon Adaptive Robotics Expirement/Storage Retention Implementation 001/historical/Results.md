# Historical compaction: bounded proof passed

**Recommendation: a later explicitly authorized historical event/motion migration appears worthwhile.** This raw-byte codec reduced four complete representative event/motion pairs from **3,904,266,533 bytes to 162,341,200 bytes**, a **95.842% reduction**. Every restored file matched its original by direct streaming byte comparison and SHA-256. Originals remain unchanged and retained; this prototype therefore adds about 162 MB of ignored archives rather than reclaiming space now.

The shared-queue job `20260927T005213981019Z-fc76ddc7` officially **succeeded with exit status 0**. Its [receipt](queue-receipt.json), [detailed qualification](qualification.json) and eight [source/archive manifests](manifests/) are retained. This is measured evidence for four purposively selected runs, not a measured all-r4 saving or a statistically representative compression estimate.

Events alone compressed from 3,712,668,874 to 109,299,424 bytes (**97.056% smaller**). Motion compressed from 191,597,659 to 53,041,776 bytes (**72.316% smaller**) with every original 100 Hz row and full numerical spelling preserved. These are container byte totals, excluding the small sidecars and reports.

The cases include the longest event stream in the prior complete 264-run audit (baseline C20), long A1/A3 runs, 169 model requests, three restart episodes, a late A1 model response, partial/failure outcomes, and the A2 C14 fixed 30-second model timeout with terminal/model error evidence. There are 12,104 exact `content_utf8` occurrences in the selected decision/restart records. The largest measured retained checkpoint/file text is 12,865 bytes; the largest complete candidate-input event is 117,665 bytes and the largest protected restart envelope is 141,377 bytes. These are within-selection maxima, not global maxima. The codec also passed multiblock arbitrary-byte payload tests; it has no JSON-line-size restriction.

The complete deterministic outputs are equal; only the diagnostics creation timestamp was omitted. Packing all eight files took **48.29 seconds** in summed per-file measurements, including archive hashing. Restoration took **16.87 seconds**, before the extra independent digest/byte-comparison passes. The complete queue job, including unit tests, coverage profiling, verification and semantic comparison, took **113.35 seconds**. These timings are for this host and this run, not an operational performance guarantee.

At most one restored file existed at once. The largest temporary restoration was **1,718,720,109 bytes**. The measured logical peak of retained prototype archives plus the active restored file was **1,755,682,844 bytes**. Small manifests/reports, filesystem allocation overhead and diagnostic RAM are outside that logical disk figure. The scratch directory was empty at completion. Original file hashes, sizes and modification times matched; no historical event, motion, result, manifest, image or checkpoint was deleted by this prototype.

Nine focused tests passed in the authenticated queue job: arbitrary binary bytes, empty files, exact JSON spelling/key order/duplicate keys/line endings, multiblock payloads, existing/source output refusal, truncation/corruption/trailing bytes, wrong manifests, oversized allocation declarations, and invalid pack destinations/chunk bounds. See [README](README.md) for the versioned format, streaming reader, restore commands and bounds.

The remaining risk is operational compatibility, not a demonstrated byte loss: unchanged frozen readers expect ordinary original filenames, so a later migration needs a verified restore/availability layer and a complete all-file provenance/restore checklist. This prototype does not establish random access, cross-run deduplication, power-loss recovery of an interrupted pack, or every legacy tool's end-to-end behavior. A partial pack remains unqualified; an interrupted restore must be retried to a new output after inspection. Full historical migration is therefore **recommended for a later decision, not authorized or executed here**. It need not block the separately scoped Robot-Codex integration work once the other storage prerequisites are met.
