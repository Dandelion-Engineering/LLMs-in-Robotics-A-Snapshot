# Complete evaluation derivative accounting

[process_evaluation.py](process_evaluation.py) is a queue-only operator processor for the protected 264-attempt release. It is implemented and synthetically tested; it has not processed actual evaluation evidence or rebuilt production HTML. Its first operation verifies the exact script's current queue ownership. It never calls queue submit/status, starts simulation/model work, draws seeds, changes the canonical map, alters original results, or chooses replacement attempts.

The processor imports [collect_results.py](../Batch%2001/Release%20Analysis/collect_results.py) read-only. That collector validates the full planned matrix, finalized terminal/batch/official receipt hashes, original canonical binding and complete supersession chain. Canonical corrections govern selected outcome and clocks, with raw/wrapper infrastructure invalidity preserved. A missing terminal stays missing; an invalid source binding refuses collection before output creation. Full canonical map validation and hashes are retained alongside the selection.

Use the exact queued command in [RUNBOOK.md](RUNBOOK.md). The CLI arguments are `--release-dir <protected-release>` and `--output-dir <fresh-operator-directory>`; optional `--map-root` defaults to the canonical Architecture Map. Output must be outside the release, raw originals, Runtime, canonical map and any candidate-state directory. No output file is overwritten. These files are operator artifacts and must not be exposed to a candidate.

The output contains:

- `selected-results.json`: the collector's flat result list, provenance, missing-terminal records and canonical/implementation identities. This is usable by `protocol.py analyze`; it is not an analysis result itself.
- `selection.json`: queue identity, protected control-file and implementation hashes, selected-results reference and whole-block infrastructure exclusions.
- One directory for **every planned run**, with `status.json`, successful `diagnostics.json` and `continuity.json`, or separately hashed `*-failure.json`. Missing inputs have explicit unavailable statuses. A terminal without a bound complete supervisor result cannot be interpreted as an ordinary completed episode.
- Append-only `progress.jsonl` and final `index.json`. The index retains public plan columns, canonical selected result, per-run source references/status and small metric/coverage summaries. Full event/trajectory/opportunity records remain only in linked per-run files. The processor writes no HTML and embeds no full traces.

Diagnostics and continuity run sequentially inside the owned queue process. Each can fail independently without erasing the other report. Per-run source bytes, exact raw evaluation identity/authorization and implementation/control hashes are checked before and after derivation. Protected release/manifests, all canonical map files and batch authority files are rechecked at finalization. A changed global authority snapshot invalidates every final primary derivative eligibility, including earlier reports; the final index explicitly overrides their immutable creation-time status/progress. Files and recorded scientific validity are never rewritten to hide that event.

Descriptive groups use architecture, persistence condition and horizon. They provide both all-planned descriptive accounting and the primary-eligible subset. The latter mirrors the protocol disposition rules: any infrastructure-invalid selected result excludes its **whole paired block**, including other entrants/conditions; unknown/invalid validity or missing outcome does not qualify, while a valid task failure does. A derivative must also have unchanged verified sources and no integrity findings to contribute measurements. These checks do not upgrade or replace canonical validity.

Every numerical summary reports its observed-run count, missing measurements among accepted reports, and missing/unverified report count. Means and medians weight each observed run equally; they do not pool calls or trajectories across unequal episodes. Existing sampled motion, pause support, model counters, machine-busy time, transport coverage and raw contact measurements retain their original units and limitations. No normalized-jerk winner or matched-motion claim is computed. Missing values remain null, including absent token measurements and empty measurement groups.

Continuity reports retain planned/unobserved/exercised opportunity counts, known admissible/inadmissible and unknown admissibility separately. Recovery rates divide only established recoveries by reported known-admissible exercised opportunities, with an explicit report denominator and missing-report count. Missing runs are never assigned zero opportunities or failed recovery. Legacy recorded/annotated admissibility and independently qualified admissibility have separate counters. The new [qualified restart adapter](Qualified%20restart%20verification.md) independently binds release/run/freeze, rehashes frozen helpers and calibration artifacts, recomputes the classifier and verifies the actual frozen absence endpoint. Missing context, unsupported first control and exceeded/missing absence remain unknown. The upstream loader is now integrated; production use awaits its final freeze and real qualification. Embedded verification assertions alone are insufficient.

The builder now accepts `--evaluation-index <index.json> --evaluation-receipt <official-receipt.json>`. [derivative_adapter.py](derivative_adapter.py) verifies finalized receipt identity, the release and selected-result references, every planned ID, complete accounting, report/failure-file bytes, propagated whole-block exclusions and descriptive-summary arithmetic. It embeds only compact rows and groups; full reports remain linked. Missing and failed derivatives retain different statuses. A recorded global integrity failure disables all primary derivative measurements; a historical changed canonical snapshot is explicitly labeled rather than promoted. Original raw streams are not reread for this catalogue.

The source-bound [analysis wrapper](../Batch%2001/Release%20Analysis/analyze_results.py) writes unchanged protocol estimates plus `analysis-provenance.json`. Supply that sidecar and its successful official receipt with `--analysis-provenance` and `--analysis-receipt`. [analysis_provenance.py](analysis_provenance.py) verifies the exact inputs, protected manifests, frozen protocol, before/after inventories and settings. If both the diagnostic index and analysis are supplied, they must bind the same selected results and release. Legacy analysis without a sidecar retains the weaker source-byte/structure label. None of these adapters change estimates, selected outcomes or the fixed 12 trace slots.

Exit 0 means all planned derivations finished; task failure, invalid canonical results and derivative integrity findings can still be present and remain labeled/excluded as appropriate. Exit 1 retains a finalized index with missing/failed processing or global integrity failure. Exit 2 refuses an invalid entry/selection. Always retain the actual queue receipt, including exit 1; do not describe a partial queue job as successful. A process interrupted before `index.json` has no finalized derivative batch.

[test_process_evaluation.py](test_process_evaluation.py) currently has 11 bounded tests: 264 planned slots with 263 missing attempts, corrections over raw success, valid failures, whole-block infrastructure exclusions, missing evidence, independent derivation errors, unfinalized batch refusal, source/global map mutation, exact episode authorization, fresh output protection, and a tiny fixture calling both real derivation APIs. These tests use temporary synthetic files and mocked queue ownership only. They are implementation checks, not experimental observations.
