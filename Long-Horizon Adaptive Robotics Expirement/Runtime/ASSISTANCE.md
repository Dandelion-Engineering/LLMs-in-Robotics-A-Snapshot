# Scripted assistance implementation

`experiment.ScriptedAssistance`, policy `public-reobserve-advice-v1`, implements the common simulated help channel. Every unique help request records its reason, public evidence references, and requested information/action. The supervisor retains accepted requests and answers outside candidate state, so both persistence conditions receive the same durable public answers after a restart. Invalid requests are retained and rejected; they still count as requesting help.

The same approved answer becomes available only after both wall time and simulation time have advanced at least 15 seconds from the request. Physics continues. The answer advises obtaining fresh public observations, checking location, inspection, station status and the effective order, preserving uncertain action outcomes and missing provenance, and avoiding ambiguous replay. It reveals no evaluator state and performs no physical rescue. The exact answer, policy identifier, clocks, waits, request/response event links and delivered packet are retained in the manifest and event evidence.

Candidates consume each answer identifier once per retained state. A new answer releases the help halt and starts another bounded model-attempt round using a fresh public packet. It clears stale proposed procedures, but preserves unresolved actions, physical failure counts and process/inspection evidence. Reconciliation still requires public evidence; advice alone cannot prove execution or reconstruct history. Lost private state in the no-persistence condition does not erase public answers.

Any help request makes subsequent completion assisted, including a rejected request or a request whose answer arrives after completion. Result records separate unassisted completion, completion after help, requests, responses, pending responses, summed waiting, and physical rescues (zero for this policy). Waiting sums may overlap when requests overlap. Human time is explicitly unmeasured: this is simulated assistance, not measured operator workload. Help does not end ordinary episodes early or waive their time cap. The separate permanent-fault/missing-stock escalation diagnostic is not implemented by this advice channel.

Resource observations run in one background sampler through cell/candidate startup, the episode, candidate restarts, and cleanup. `resources.jsonl` is hashed in the result, with explicit missing metrics and incomplete attribution. Model-server startup and normal shutdown occur outside `run_episode` and are excluded from this coverage. Resource measurements are observations, not evidence that all published resource limits were enforced.

World and policy/noise seeds are separate. `--seed` remains a checked alias of `--world-seed`; `--policy-noise-seed` is sent to both the camera-noise hook and actual local-model requests. Sensor random state is supervisor-owned and survives candidate restart. Greedy model decoding can remain unchanged across different policy seeds; camera-noise differences are still applied before perception. Seeds remain evaluator-side metadata and are not included in candidate packets.
