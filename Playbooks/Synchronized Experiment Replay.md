# Synchronized Experiment Replay Playbook

## Purpose and boundary

Make an experiment inspectable as a sequence: world → observation → observable agent/tool behavior → action and authority → files → controller follow-through. Scrubbing, playback, event jumps and file selection must share one cursor. This is derived inspection tooling; it never reruns an experiment, repairs an outcome, changes retained evidence or exposes hidden reasoning.

Read the [HTML report playbook](HTML%20Interactive%20Reports.md), the experiment's current authority and retention contract, and the applicable result records first. Use an isolated output directory outside every frozen source/evidence inventory. A failed, unknown or unrun attempt keeps its original disposition. Queue success is an execution gate, not a scientific verdict.

## Execute the playbook

1. **Authenticate inputs.** Obtain official queue state and require successful integer exit 0 before consuming successful-run outcomes. Bind the disposition to its assessment, that assessment to the manifest, receipt, frozen revision and evidence inventory, and every consumed trace/snapshot/recording to its original hash and size. Inventory video availability, timestamp fields, filesystem snapshots and tool capture completeness. Record input hashes before building and verify them again after QA. Never read or publish credential/configuration secrets as replay material.
2. **Choose the spine from actual evidence.** Use recorded simulation time for world events and frames when available. Keep capture, publication, request, execution, completion and application receipt clocks distinct. Do not infer a frame's wall time from an image index or assume simulation time equals elapsed wall time. For cross-clock events, bracket their recorded wall time between adjacent world clock anchors; retain both anchor IDs, interval endpoints and original clocks. A central interpolated value can aid navigation, but is derived. Reveal an uncertain event only at its upper bound so it cannot appear prematurely. Check clock regressions, duplicate times, identity joins and maximal bracket width. Never extrapolate across a clock reset or an unobserved boundary.
3. **Preserve stops and untimed material.** Records after simulation stops belong to a visibly separate terminal tail. Untimed final snapshots are accessible in a final/terminal view, never backdated into the running experiment. Keep other unalignable records in an explicit untimed section. Order simultaneous events by retained source sequence within a source; do not claim causal order from a tie across sources.
4. **Build the observable stream.** Allowlist public messages, public tool requests/results, executor stdout/stderr, robot requests, protected action/authority receipts, observations, handbacks and controller transitions. Exclude reasoning items, reasoning deltas, raw model response envelopes, account/credential records and hidden deliberation. Use request, process, command and observation IDs to connect layers. An application output projection and executor output are different evidence; preserve their labels and byte/hash checks. A request, HTTP success, completed action and accepted transfer are different events.
5. **Reconstruct only evidenced files.** Start from retained initial names/hashes/bytes, then use content-bearing reads, successful bounded writes, protected commits and later snapshots. Record path, bytes/hash, evidence source, observed/write interval, confidence and any before/after content identity. Do not execute historical code to reconstruct a write. Parse only a closed, audited subset of retained literal write syntax; cross-check derived bytes against independently retained content. Display unknown contents when only a hash survives. Label a last observed version as such: absent a complete mutation journal, it is not an exact intermediate filesystem. Diff adjacent evidenced versions; distinguish a proven initial absence from an unknown before-state. Preserve deletions, renames, symlinks, binaries and omitted scope when retained, and explain unavailable metadata.
6. **Build the synchronized interface.** Put world playback and its simulation cursor first. Include play/pause, speed, scrub, numeric seek, previous/next meaningful event, semantic jumps, event/category filters, selected-event details and source links. The cursor updates the world, owner/controller, observations, public stream, file tree, selected content and diff together. Selection must persist when scrubbing; when its file has not yet been evidenced, show an empty/unknown state. At the end, expose every retained final file. Do not silently fill frame gaps: use explicitly stale recorded pixels or a separately labeled observation/state schematic with age and sampling limits.
7. **Verify evidence independently.** A verifier separate from the builder must recompute original hashes and clock brackets, join every displayed original frame by capture time to its public publication, verify content and diff hashes, compare the complete final file inventory with its snapshot, and check meaningful event IDs directly against raw receipts. Test no-future visibility immediately before/at/after boundaries, post-stop handling, missing clocks, content gaps, unknown before-states and exclusion of reasoning. Verification must fail on corrupted inputs and inconsistent joins.
8. **Test the actual artifact.** In a browser, test playback, speed, arbitrary scrubbing, every semantic jump, next/previous, all filters, empty searches, event selection, source links, file selection, changes/diffs, and final browsing. Inspect recorded-image and schematic states, layout at desktop/mobile sizes, keyboard access, console errors and local/loopback loading. Static tests do not establish browser behavior. Retain failed QA attempts and the repairs. Feed lessons back into this playbook, publish a short evidence/limitations handoff, and stop at the requested review boundary.

Use the project's shared queue for sustained decoding/export/build/verification work. Authenticate each queued job's terminal state before using its outputs. Store derived manifests, QA receipts and browser screenshots beside the replay. Keep source links relative where possible and provide a normal local HTML entry point; document any temporary loopback preview without making it a permanent service.

## Prospective capture contract

Before a future experiment is authorized, propose these additions as a new versioned recorder contract; this playbook does not authorize changing a frozen campaign:

| Capture | Needed evidence |
|---|---|
| Clock bridge | Run/invocation IDs, simulation tick/time, host monotonic/QPC clock and wall clock in one trusted record; reset segments, synchronization uncertainty and dropped-record counts |
| Camera/video | Camera ID, frame ID, capture tick, publication/availability time, codec PTS → simulation-time manifest, frame hashes and explicit gaps; enough storage for the declared episode, without weakening retention protections |
| Observable tools | Stable public tool/item/request/process IDs, request/start/output/exit/receipt times, complete bounded output and hashes; record observable channels without private reasoning |
| Workspace baseline | Complete initial tree, file bytes/hash, metadata, symlink targets and inclusion/exclusion policy, captured after setup and before model tools |
| Mutation journal | Trusted create/write/truncate/rename/delete/link operations with atomic boundaries, sequence, old/new content hashes and retained content objects; temporary files, partial writes and failed attempts too |
| Checkpoints | Periodic complete manifests and content objects bound to journal sequence and clock bridge; verify reconstruction against checkpoints rather than assuming journal completeness |
| Final namespace | Timestamped final snapshot before teardown and a separately bound post-teardown snapshot; explicit omitted credentials and filesystem roots |
| Action/controller | Requested/admitted/dispatched/terminal IDs, authority epochs, observation used and controller transition/handback receipts |

A reusable adapter should emit the [normalized replay contract](../Tools/synchronized_replay/README.md); the viewer should not need experiment-specific parsing. Automate identity validation, gap reporting, content-addressed export and boundary QA. Treat missing capture as missing evidence, never as permission for retroactive instrumentation.

## Home01 reference and lessons

The [Campaign 002 Home01 replay](../Long-Horizon%20Adaptive%20Robotics%20Expirement/Robot-Codex%20Integration%20001/campaign-002/investigation/replays/home01/README.md) is the reference execution. It retains the rejected first handback, protected setup B, accepted second handback and conventional follow-through. The implementation/audit record belongs beside that derived replay. Its initial limitations established during inventory are sparse RGB ending before both handbacks, hash-only mutable initial files, a complete retained final workspace export with endpoint omission, six protected continuity contents, and no complete filesystem mutation journal. Do not confuse public observations with exact bytes of periodically mirrored files.

The implementation added these lessons:

- A setup hash for a mirrored `live/state.json` does not have to match bytes read later. Authenticate the later bytes through complete executor capture and retain their new identity. The first derived build failed this mistaken comparison; the repair preserves both identities.
- Public world samples describe the world and what was available through the gateway. They do not prove that the agent read every sample. Keep the selected model/tool request and its result beside the observer's world sample.
- Exact clock bridging was bounded to adjacent original receipts, with a maximum 150 ms simulation interval in Home01. Present that bound rather than calling the interpolated navigation estimate exact.
- A successful literal note write can precede its protected atomic continuity commit. Both records matter. The six protected content hashes independently corroborate the literal-write adapter, including a bounded `sed` edit; no historical code is executed.
- The final local outcome note and final model message occur after world stop. The terminal view preserves their later wall times and makes the untimed final namespace available without inventing a simulation-time write.
- Keep a numeric Go action in addition to drag/keyboard scrubbing. Test it in the actual browser; the provisional fill/blur check exposed an unreliable seek interaction.
- Fit world, public stream and files side by side on a wide desktop, and stack them on a phone. Scale schematic labels with rendered canvas size so retained object IDs remain legible.
- Raw JSON previews can be blocked by the in-app browser. Preserve that browser boundary, verify local source identities/links separately, and keep exact allowlisted observable details readable inside the replay. Never link public UI directly to the raw client log containing private reasoning.
- Preserve exact bytes of hash-bound exports and implementation snapshots across Git checkouts. Check scoped attributes before closeout; automatic LF/CRLF conversion can otherwise invalidate a correct artifact identity. Home01's derived candidates inherit the existing experiment subtree protection, and the new reusable tool folder has its own byte-preserving attributes.

## Campaign 003 exact-journal lessons

The [revised-envelope investigation](../Long-Horizon%20Adaptive%20Robotics%20Expirement/Robot-Codex%20Integration%20001/campaign-003/investigation-002/README.md) retains the data/browser failures and their isolated repairs.

- Build per-path version indexes in one forward journal pass, with explicit hard-link, rename, removal and metadata handling. Repeated backward reconstruction can stall the browser even when final hashes are correct. Keep semantic-jump controls bounded and test selection before creation, after deletion and at final state.
- Include failed handbacks and admission rejections in semantic navigation. A successful worker does not imply a successful task: verify qualification/scored stage labels, attempted/not-run counts, controller ownership, fresh-session boundaries and complete allowlisted public-event membership against retained receipts.
- Retain actual browser screenshots beside the derived artifact and authenticate their bytes after QA. Requested CSS viewport dimensions and returned screenshot raster dimensions can differ; record both. After resizing, obtain settled state before accepting the capture. Preserve failed checks, verify loopback provenance targets independently when raw JSON display is blocked, and stop temporary servers at handoff.
